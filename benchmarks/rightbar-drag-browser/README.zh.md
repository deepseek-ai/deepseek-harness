# 右侧栏拖动浏览器基准

[English](README.md) | 中文

[rightbar-drag.bench.ts](rightbar-drag.bench.ts) 中的必需 Chromium 用例在一个已加载全部更早分页的 120 轮合成会话旁拖动右侧栏的宽度拖拽条，并统计拖动期间重算样式的元素数和布局次数。随产品发布的 Web 测试脚手架提供隔离的 home、持久化和回环监听；Chromium 加载已构建的 Web 产物。

## 运行

`pnpm run test:bench` 先构建库、worker 和 Web 产物，再运行串行基准清单。产物已构建时，可通过 `pnpm exec vitest run --config vitest.bench.config.ts benchmarks/rightbar-drag-browser` 只运行本目录。导出了 `NODE_USE_ENV_PROXY` 的 shell 需要先取消它，这是[测试代理设置](../../scripts/test-proxy-environment.ts)的要求。

## 测量

每次 Chromium 追踪覆盖一次真实鼠标拖动，直到松开后的两个动画帧。基准使用两个全新的浏览器进程和脚手架环境，均隐藏会话面板。

- **列宽变化：** 每个样本都在 1680×1000 视口中把右侧栏加宽 40 步（每步 8px），再拖回。实际渲染的正文列必须随侧栏加宽而变窄、随侧栏缩窄而变宽；起止列宽都必须低于 680px 的正文宽度下限。
- **列宽固定：** 第一个样本还在单独页面中打开相同的 120 轮记录；该页面使用独立存储，视口为 2560×1000，预存的正文宽度为 720px。侧栏展开动画结束后，从 1152px 到 1232px 再拖回，每个方向 40 步，每步 2px，可见侧栏必须逐步到达目标宽度。每次观察到的正文列宽都必须是 720px。会话面板的停靠探针上，标记预留空间是否足够的值必须从 1px 变为 0px，再变回 1px。

- **样式重算：** 各次样式重算报告的元素数之和除以页面元素数。列宽变化时，每个方向的上中位数不得超过 1（即一整个页面的元素数）。列宽固定时，每个方向的比值不得超过 0.10。
- **单次样式重算：** 每个样本都输出 `restylePassesByElementCount`。例如 `"3": 40` 表示 Chromium 有 40 个完整的 `UpdateLayoutTree` 事件各自重算了 3 个元素。这不是整段拖动去重后的 DOM 节点数，也不是失效原因条数。`peakStyledElements` 是单个事件的最大元素数；`peakCountPassMs` 是该事件的耗时（元素数并列时取较长者）。正文固定时，加宽和缩窄的每次重算都不得超过 512 个元素，即使累计比值合格也一样。
- **布局：** 列宽变化时，每次拖动必须产生至少一个 `Layout` 事件。`layoutCount` 统计所有布局；`scriptNestedLayoutCount` 只统计起止时间均落在同一进程、同一线程的脚本事件内的布局，每次布局只计一次，动画帧回调也算脚本事件。每次拖动此项不得超过 20（鼠标步数的一半）。嵌套关系是判断同步布局的间接指标，并不说明每次嵌套布局都多余；脚本以外的浏览器重排不占用该预算。

帧间隔的 p95 和最大值（`frameP95Ms`、`maxFrameGapMs`）覆盖手势至松开后两个动画帧，不包含追踪启动和解析。帧间隔、样式重算耗时和布局耗时仅作诊断；工作量预算不随 CPU 速度缩放。
