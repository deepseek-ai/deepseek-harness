# @deepseek-ai/dsh-creation-recommendations

[English](README.md) | 中文

## 概述

用户明确提出界面需求、隐含表达清晰的查看或编辑需求，或任务结果有具体的后续用途时，Agent 先回答，再视情况在本轮末尾提供一张可选创建卡片。明确提出的界面可以只服务一次任务。用户可修改建议位置，再选择创建。后台 Creator 生成一个新插件并安装到配置档案；保留用于确认继续使用，撤销则移除该插件，恢复会重新安装它。

## 使用本包

打开插件 → 更多 → 实验性插件，启用[个性化推荐](../personalized-recommendations/README.zh.md)，其中的个性化页面行就是本包。内置配置档案默认不启用此插件。启用后在插件一级页显示，关闭后仅保留在二级页。个性化推荐 Bundle 同时启用共享的[操作卡片服务](../action-cards/README.zh.md)及其浏览器端；该服务的 `queuedMessageLimit` 规定为下一轮排队的消息达到多少条时，卡片工具拒绝本轮的卡片。用户明确指定的位置优先；否则 Agent 根据作用范围和交互方式推荐：

| 位置 | 用途 |
|:--|:--|
| `sidebar-right` | 与 Session 关联的查看器、编辑器或 Context 检查，显示在对话右侧。 |
| `page` | 与 Session 关联的流式输出或交互，在对话、轨迹旁新增 Tab。 |
| `sidebar-left` | 全局功能：左侧入口打开主区域独立页面，不显示对话、轨迹 Tab。 |

左侧入口和全局页面属于同一落点，也适用于全局流式工具。“边看边聊”意味着需要同时可见，使用右侧栏，实时日志也适用。否则默认选位先区分全局与 Session；Session 内的流式输出或交互优先使用顶部 Tab，其余查看器、编辑器放右侧栏。仅要求后台任务不阻塞对话，不代表需要同时可见。未绑定任务或 Session 的长期个人记录默认全局页面；仅在当前对话提供数据，不代表绑定当前 Session。任务或 Session 内的查看器默认放右侧。仅当缺失的范围信息会改变结果时才澄清。

卡片还提供“自行撰写”。手写位置优先于早先的位置描述，并保存在接受记录中。Creator 按需读取三种位置指南，通过现有 DSH 扩展点实现，不增加第四种 Slot，也不额外调用路由模型。无法支持的位置应报告失败，不得悄悄替换成其他位置。空白或超过 1,000 字的输入在启动子任务前被拒绝。

个性化页面可独立使用。它为工作和个人任务规划新界面，不局限于 DSH 功能。只有需求符合页面规划条件后，Skill 才使用当前官方插件目录避免重复创建。询问现成功能不加载此规划 Skill。匹配到现有插件时说明它在插件页的入口，不出卡片。

明确提出界面需求时，不要求反复使用或数据变化。用户要求文件、代码片段或修改现有项目时，保留该交付形式；内容可视化或可交互本身不构成安装插件的理由。没有界面请求时，推荐需要当前回答无法提供的具体后续操作，例如维护记录或探索变化的结果；仅重新包装静态正文或表格不够。修改已有页面沿用该页面的开发流程，此创建动作不以新插件替代原页面。只要求讲解改法时，不调查源码。持久化、手动维护、打开时刷新和关闭后自动更新是不同需求。

面对多个独立需求，指引要求回答只选定一个页面方案。优先遵循用户明确指定的顺序，否则先推荐现成插件。其余需求在正文说明。仅当缺失信息会改变功能结果时才澄清，不从另一个愿望推断用途或数据来源。被拒绝的建议不会生成卡片，也不会安排未来自动出卡。选定现成插件后，无需为未选中的页面需求查询目录。这些语义指引补充 Host 每轮最多一张卡片的限制：一轮里只有第一个被接受的 `propose_action` 调用会成为卡片。

### 操作结果与恢复

卡片在被接受的调用所在轮次结束后出现。尚未创建的方案在后续人工消息之后仍然可用，包括对方案的追问。同一会话里的下一个方案会替换它：旧卡片显示“已替换”，没有创建控件，Host 也会拒绝对它的过时点击，因此每个会话只有一张未开始的卡片。刷新、切换视图和后台通知不会改变卡片。已开始的任务保留进度和重试控件。替换由后来的方案推导得出，不是新的持久化决定记录。当用户为后续轮次排队的消息达到 `queuedMessageLimit` 条及以上时，卡片工具拒绝该方案，因此不会出卡。

创建要求当前会话是活动的根会话、连接有权修改配置档案，且 Session 的沙箱模式不是只读：Creator 继承该模式，因此只读 Session 拒绝创建，卡片保持未开始。生成阶段可取消，子任务清理完毕后才能重试。安装开始后显示“正在安装”，等待已接纳的操作结束。关闭或离开会话不会卸载已完成的插件。重新连接后会恢复操作记录；任何卡片操作（包括“暂不需要”）之前，都会对照已安装插件检查中断或结果不明的创建，因此页面其实已安装的不明结果会显示“已安装”和撤销，而不是被忽略。移除失败时保留已有记录和实际生效结果，以便重试。卸载推荐插件会停止它负责的 Creator 任务和本地后续处理。已接纳的配置变更由插件管理器负责，可能在重载后完成；重新打开会话时先检查安装状态再允许重试。已安装插件仍然保留。恢复只确认安装，不根据配置中的开启标记推断运行时已生效。

撤销会卸载插件，但保留其文件。已移除的卡片提供“恢复”：重新校验配置档案中保留的副本并重新安装，不运行 Creator；与创建一样，需要活动的根会话和修改配置档案的权限。副本缺失或校验失败时拒绝恢复，需要重新提案。

下一次自然发起的模型请求会收到各张已变化卡片尚未告知模型的最新状态。状态更新不会唤醒对话，也不授权其他动作。Session 投影只在状态上下文写入日志后确认送达，因此取消、重载和重新打开会话都保留未送达的更新。一次请求之前发生的多次后台变化合并为最新记录。

## 实现原理

<details>
<summary>实现细节 — 点击展开</summary>

Host 入口是注入 `actionCards` 的普通函数插件；它不提供自己的 service 或 Remote，也不向 `dsh-base` 增加任何内容。关闭功能插件时移除它的 Skill 和卡片种类，并清理其负责的 Creator 任务。

插件向共享的[操作卡片服务](../action-cards/README.zh.md)注册 `create_personalized_page` 种类：`personalized-pages` Skill、含 `slot` 和可选 `initialContent` 的 `details`，以及创建、保留、撤销、取消和恢复五个操作。该服务负责 `propose_action` 工具、卡片投影、“暂不需要”、Remote 操作和状态通知。本插件处理其余操作，记录的决定数据包含位置、手写位置、预留包名和最近一次安装结果；状态通知报告其中除包名以外的字段。每次操作之前，插件的 `reconcile` 会对照已安装的配置档案检查中断或结果不明的创建；之后，尚未开始的卡片，以及已取消、失败、中断或结果不明的创建，都可以记录“暂不需要”。

卡片工具承载类型化提案，定义点击后执行的语义；各种类提供自己的字段和 Skill 入口。`personalized-pages` 负责适用条件、查重、最小范围、选位和内容准备。它允许补齐实现已确认行为所需的细节，例如输入校验和空状态；新增独立操作、数据源、自动任务或访问范围，需要用户请求或已确认上下文的依据。

Host 预留新包名，通过 `subagents` 启动已有的 `cordis` 预设，传入完整需求和选定位置。子 Agent 在父会话原工作区的 `.dsh-created-plugins/<id>` 下生成文件，保留委派时的文件权限。Creator 运行期间，它和在它之下创建的每个 Agent 只能通过 `plugin_manager` 列出插件、Bundle 和版本豁免；安装由 Host 执行。Host 校验包身份和仅允许新增的普通 YAML 或 JSON 补丁，将结果复制到配置档案的 `created-plugins` 目录并再次校验，再调用 `pluginManager.installBundle`；安装后的插件不依赖原工作区。补丁只能添加该新包自身且名称唯一的非分组条目；不接受自定义 YAML 标签、别名或 include。每个条目必须能解析到已构建的 JavaScript 文件；声明了 `dsh.client` 的包还必须导出已构建的 `./client` JavaScript 入口。相对符号链接必须留在包内，复制时保留原目标。共享的 Session 投影保存建议和操作记录。恢复失败时仍可打开会话，卡片显示结果不明；重试必须先检查配置档案。后台完成结果写入重新打开的当前 Session 实例。并发点击共用一次操作；投影每轮只接纳一个提案。

Creator 收到已接受的完整方案、优先于早先位置描述的用户最终选位，以及本插件随包提供的位置指南。执行请求允许调研实现细节，但不得扩大已接受的行为和数据范围；业务含义不明导致无法忠实实现时，应返回 `ready:false`。位置指南补充 `cordis-plugin-development`，在 API 调研前提供注册、状态和卸载指引。卸载时应移除自己的界面和页签，保留其他内容；这些是模型执行要求，不是静态包校验。

`brief` 同时用于卡片和 Creator，承载行为、输入、计算方法与持久化范围。可选的 `initialContent` 只承载所需的原始条目、数值、对应关系、单位和统计周期，缺失值仍保持缺失。原始条目即使描述了动作，也仍是待展示内容。主 Agent 在提交前检查这项分工，并将“这些条目”等指代补成实际内容，因为子 Agent 无法读取主对话。Skill 末尾有七个短示例：三个交接示例展示 `brief` 与 `initialContent` 的分工，四个不出卡的请求。会改变计算结果的口径歧义，需要在方案确定计算方法前澄清。

两个字段均可从日志恢复并原样传给 Creator；这保证文本不丢失，不保证语义准确或完整。省略 `initialContent` 表示未提供已有内容。用户自行维护的空白页面无需旧资料，也不得承诺自动导入聊天；明确要求预填时则需要原始内容。已命名但未检查的数据源仍是未验证的依赖，响应格式和连接方式留待授权后的 Creator 调研。

## 模型体验

### 创建建议

#### 模型看到的内容

已有 `skill` 工具在用户明确提出界面需求、隐含表达清晰的查看或编辑需求，或结果有具体后续用途时加载 `personalized-pages`。简短目录描述这些适用条件，不逐项列举插件场景，也不新增公共 system prompt。加载后返回规划和位置指引，以及供查重的当前官方插件名称、描述和启用状态。目录不负责触发规划，也不是内置 UI 的完整清单。询问现成功能、修改已有页面、普通回答或开发、引用中的愿望、只讨论及已拒绝的请求不需要创建卡。明确提出的一次性界面仍可出卡。查看本应用自身数据（会话、任务、日志、工作区文件）的实时视图，不需要明确要求页面也可出卡。已有能力合适时不再提重复页面方案；无法确认的细节保持明确。提案是与加载 Skill 同一轮中的一次 [`propose_action`](../action-cards/README.zh.md#model-experience) 调用，含 `action: "create_personalized_page"`、`title`、只写请求或必要行为的一到三句 `brief`，以及 `details`：其中有 `slot`，可选的 `initialContent` 用于已提供的数据，不编造行或单位。调用本身就是提交；用户点击创建之前不会开始任何工作。先给方案、只读模式仍允许提交建议。邀请指引随被接受的调用结果给出，而不在 Skill 中，因此只有卡片存在时，回答末尾才用一句简短邀请说明后台创建、耗时和 token 成本以及点击创建；只有点击创建才后台启动 Creator；Agent 不等待、轮询、声称已安装或要求刷新、报告完成。

#### Token 影响

启用后，请求带 Skill 目录里的一条摘要；共享的卡片工具只在此 Skill 加载后才声明。完整规划策略、交接示例和当前官方插件描述由 `skill` 按需加载。一次创建推荐需要一次 Skill 加载，并在最终回答前调用一次 `propose_action`。只有用户接受创建后，才会产生后台 Creator 调用。卡片的信息按钮说明生成可能耗时较长、消耗大量 token；查看说明不会启动任务。

#### KV Cache effect

Skill 内容和建议元数据追加到对话；加载 Skill 不改写公共 system prompt。开启或关闭本实验会添加或移除它的 Skill 目录条目；卡片工具只在 Skill 加载后才加入声明，见[操作卡片](../action-cards/README.zh.md#model-experience)页面。安装生成的插件可能改变后续工具声明和缓存复用。变化后的卡片记录会以简短状态通知追加到下一次请求；状态不变的卡片不重复增加上下文。该通知由共享卡片服务在请求准备阶段追加，不增加模型调用。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 只支持新增插件；修改已有插件留待后续。恢复只重新安装卡片记录对应的配置档案副本，不提供版本历史。
- 意图识别依赖模型语义。指引不强制工具选择或事实依据：Agent 仍可能多余地查看文件，或推断目录没有说明的能力。生成代码使用现有 Creator 权限执行，包校验不构成代码沙箱。
- 成功、失败、取消及撤销后均保留工作区源目录和配置档案副本。撤销移除已安装插件及其界面，不删除这些文件。卡片会说明源码位于原工作区的 `.dsh-created-plugins/` 目录。历史记录不会持续跟踪手动插件变更。

- 暂不自动超时取消创建。关闭 Session 或关闭此实验会停止它负责的生成任务；已接纳的安装继续由插件管理器负责。
