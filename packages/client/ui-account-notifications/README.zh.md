# @deepseek-ai/dsh-client-ui-account-notifications

[English](README.md) | 中文

## 概述

在账号菜单旁展示服务端提供的账号通知。已展示卡片不会因后续列表省略而消失，并在界面语言切换时刷新内容。

## 使用此包

Web 组合将本插件与[账号设置](../ui-settings-account/README.zh.md)一同加载。本插件向 `settings.launcher.notifications` 注册内容；账号菜单提供可见性和打开账号设置的操作。通知插件负责卡片、轮询、本地化内容和交互上报。

带有已存账号的启动、登录及每次进入设置页都会启动新一轮轮询，并立即请求。`ui-account-notifications` 行中的 `notificationPollIntervalMs` 提供初始间隔，默认 600,000 ms。成功的列表响应通过 `next_poll_after` 秒替换间隔，空列表也相同。从请求结束时开始计时；失败沿用最近间隔，重启轮询恢复配置的初始值。轮询在后台继续。

账号设置拥有唯一的账号流，通过 `accountUi` 和 `account-ui/change` 提供当前状态及生命周期事件。登录进度更新沿用卡片和轮询。凭据替换、断连、权限撤销、退出登录和插件卸载会清空卡片、停止轮询并丢弃迟到响应。通知请求不等待资料或头像。通知状态不写入浏览器存储。

卡片在侧栏内部、账号入口上方渲染，位于菜单和对话框之下，不抢占焦点。宽度跟随展开的账号入口，最大为 280px，左侧留 10px、右侧至少留 10px。收起侧栏会隐藏卡片；展开后恢复卡片，不重复上报展示。关闭卡片后，下一张通过 250ms 的位置和缩放过渡补位；偏好减少动态效果时禁用过渡。

通知等待 Desktop 和模型凭据引导完成。只有前排卡片可交互并上报 `displayed`：卡片与视口相交、侧栏和文档可见并完成一帧绘制后，同一次挂载只上报一次。设置蒙层不排除该帧。已展示的前排卡片保留至关闭或过期，即使后续列表不再返回它；待展示卡片遵循服务端顺序。

每张卡片使用服务端纯文本标题、正文和有序的主要或次要按钮。所有非 dismiss 操作都携带通知 ID 上报 `cta_clicked`，立即执行并保留卡片；账号操作会打开账号设置。通过关闭按钮或 dismiss 操作关闭时，在移除卡片、下一张开始补位前只上报 `dismissed`。首帧绘制前关闭不会补报 `displayed`。过期和账号清理不上报关闭。点击上报不携带 action ID 或 target。

每次交互只上报一次，不等待、不重试；任一布尔确认结果都会结束本次尝试。上报失败会记录诊断日志，不在账号界面报错，也不撤销交互。消费状态由服务端决定：后续列表可能再次返回已关闭的卡片。列表失败保留当前卡片。

切换语言通过内容接口请求当前卡片，支持已消费通知，不重新查询列表或上报展示。内容更新保留卡片身份、顺序和焦点。读取失败保留原文并记录诊断日志；旧语言、已退登账号或已关闭卡片的响应不会恢复过时内容。

<a id="model-experience"></a>
## 模型体验

无，通知属于客户端展示数据，不进入模型请求或 Session 日志。

#### KV 缓存影响

模型请求前缀不变。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- 卡片保留现有的过期与前排保留行为。服务端文案使用纯文本；支持的操作为关闭卡片或打开账号设置。网络失败保留当前卡片，并在下次轮询时继续。

### 开发备注

包内测试覆盖生命周期所有权；Web 通知场景验证组合后的账号菜单。
