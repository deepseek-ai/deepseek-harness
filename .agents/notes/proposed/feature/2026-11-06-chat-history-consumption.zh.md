# Agent Note: Chat 历史预取与安全消费

Status: proposed

[English](2026-11-06-chat-history-consumption.md) | 中文

## Problem

只提供“加载更早”按钮时，读者必须到达已加载历史的开头再点击。提前请求可以减少中断，但请求发出时适合加载，不代表返回时适合前插：读者可能开始触摸拖动、切换导航目标，或者遇到折叠动画。分页不应为了前插历史改变已有折叠驱动或模拟惯性。

## Proposal

将历史请求与消费分开。客户端 Session 最多保留一页未消费的数据，Chat 决定是否以及何时发布它。数据保存为新页而不是旧窗口快照，所以等待不阻止尾部流式输出。类与调用关系见[技术细节](2026-11-06-chat-history-consumption-details.zh.md)。

### 手动与自动加载

手动点击保留一次加载意图：已有缓存就消费缓存，有在途请求就等待该请求，否则请求一页。数据可用后，点击绕过自动路径的动画和输入阻塞：在顶部使用首条分页锚点，其他位置采集当前阅读锚点并以分页锚点兜底，再通过既有保位路径消费，不等待动画回调。两个锚点都不存在时仍消费，但不保证位置稳定。该操作以消费、确认到头或明确失败结束。显式 Turn 跳转、返回底部、会话关闭等新的导航或生命周期变化可以取消原阅读意图。

自动加载在读者离开底部跟随、进入距历史控件两屏以内时请求。它复用已有 500ms 阅读采样及滚动结束、内容提交、尺寸通知，不新增轮询或 IntersectionObserver。代价是发现进入预取范围可能延后至下一次已有采样。

缓存是否存在与是否需要自动续接是两个事实。自动操作在低频冲突下退回按钮，不承诺等所有状态恢复；触摸与实际内层滚动仍保留续接，避免要求手机用户每次松手后再点击。

| 数据就绪时的状态 | 自动意图 | 手动意图 |
|---|---|---|
| 普通外层惯性，其他条件允许 | 浏览器原生锚定，消费 | 通过当前锚点保位消费 |
| 非顶部静止阅读 | 既有阅读保位，消费 | 既有阅读保位，消费 |
| `scrollTop ≤ 0.5`，其他条件允许 | 复用分页锚点，前插后补偿一次 | 通过当前锚点保位消费 |
| 折叠、展开或已有跟随动画 | 保留缓存，退回按钮 | 数据可用即通过既有保位消费 |
| 手指按住或实际内层滚动 | 优先于动画判断保留意图，结束后重查 | 数据可用即通过既有保位消费 |
| 鼠标按住、滚动条拖动或定位能力暂不可用 | 保留缓存，退回按钮 | 消费可用页；没有锚点时不保证位置稳定 |
| 自动预取后恢复底部跟随 | 保留缓存，取消自动消费 | 点击已暂停底部跟随 |
| 底部继续流式输出 | 本身不阻止消费 | 本身不阻止消费 |

退回按钮后，滚动、动画结束和内容通知都不能重新激活该缓存页；只有点击或显式导航可以采用它。请求和待消费页仍然互斥，不为缓存页重复请求，也不超时强行插入。

### 位置与状态展示

会话实际滚动容器设置 `overscroll-behavior-y: none`，关闭纵向边界回弹和滚动传递，不实现另一套惯性动画。自动顶部前插复用既有分页位置记录和补偿计算，只应用一次并释放；手动消费和静止保位保持原有持续保位生命周期。两种模式用相同公式恢复消费前刚采集的屏幕位置，只区别于应用后是否继续保位。一次补偿不重建采集期间的读者移动，也不重新启动惯性。即使可见 Node 顺序未变化，消费完成也会结算并清除一次补偿记录；视图关闭或历史失败时直接丢弃，不再应用。

历史控件各状态保持同高。“正在加载”和“正在处理”仍可点击，以加入当前请求或消费缓存；只有确认到头才禁用按钮。网络请求显示“正在加载”；仍有消费意图且未按住输入时显示“正在处理”；自动回退或输入按住时显示“加载更早”；失败显示“重新加载”；最后一页消费完成后显示“已到会话开头”。控件不参与原生锚定。Session 的 `historyWasPartial` 记录本实例曾显示不完整历史，组件重挂载和重连保留此事实；首次打开即完整的短会话不添加历史行。

### 范围与既有决策

不新增 `flushSync`，不改变 Conversation 发布节奏、折叠批次目标或 ScrollFollow 的跟随策略。消费准入只读内部状态和 `scrollTop`；DOM 几何读取留在距离确认和位置补偿处。不新增独立的持续开头锚点控制器、`batchShift` 或每帧补偿器。

[单一折叠运动](../../implemented/architecture/2026-10-13-chat-single-fold-motion.zh.md)与[分组树交互段](../../implemented/architecture/2026-10-11-chat-group-tree-exchanges.zh.md)仍拥有折叠和分组决策，本提案不取代它们。

## Alternatives considered

**任意状态下数据到达即前插，再持续补偿。** 需要分页接管已有运动；本方案只在顶部补偿一次，冲突时等待或退回按钮。

**所有不安全状态都自动等待恢复。** 增加低频动画、导航与自动续接的协调义务；保留触摸续接和手动完成，其他自动冲突退回按钮。

**完全取消暂存或直接丢弃冲突页。** 请求途中仍可能发生冲突，而且传输历史游标可能已经前移；保留一页比回滚游标更直接。

**运行中的 Turn 禁止加载。** 长回复期间仍需阅读历史，运行状态不能代替当前界面的消费条件。

**独立 IO 预取唤醒与 React 同步提交控制。** 复用已有采样和发布路径，接受采样延迟；没有具体失败证据时不增加提交调度机制。

## Acceptance criteria

- 请求、暂存与消费期间不重复取页；尾部流式继续更新。
- 自动退回按钮后不会被普通事件恢复；触摸、内层滚动和手动点击保留约定的续接。
- 静止和顶部前插保持旧内容位置；普通自动惯性消费不新增 JS 外层滚动写入。
- 页面失败、无进展、到头、重连和显式导航均有明确结果，不循环请求或消费过期页。
- 控件各状态同高；既有折叠驱动保持行为，真实浏览器验收区分当前构建、输入模拟和未覆盖情况。

## Risks

一次补偿恢复采集的屏幕位置，不估算读者速度。采集到应用之间的输入或浏览器移动可能影响最终运动，因此需要验证实际浏览器和输入序列。共享公式不叠加可能已包含原生锚定的滚动位置增量。见[技术风险](2026-11-06-chat-history-consumption-details.zh.md#risks)。

原生锚定适用性不能只由 CSS 支持检查保证。首次尺寸观察前不会自动预取；500ms 采样可能使高速滚动先到顶部。前插后的同步几何读取是一次补偿的成本，不能仅凭调用位置保证没有额外布局。没有可用锚点的手动消费可能移动可见内容。手动消费也可能在已有触摸手势进行中建立持续保位，约束该手势或其惯性，直到新的阅读输入释放锚点；见[手动分页限制](../../../../packages/client/ui-chat/README.zh.md#known-limitations-and-deferred-work)。

审计与测量尚在进行，本记录保持 proposed。此前 Chrome/Safari 手工反馈和不同迭代的 headless 结果不等同于最终源码的全矩阵通过；真实滚动条拖动、同页面重连、多平台输入和异常清理分支应按实际证据单独报告。
