# Agent Note: Forge Git 查询的 Session 权限

Status: implemented

[English](2026-10-28-forge-git-session-permissions.md) | 中文

## 问题

[Forge 面板](../feature/2026-10-09-forge-panel.zh.md)即使在 Session 授予完全权限时也强制使用只读沙箱。在没有可用沙箱的主机上，Session 的 shell 可以工作，检出信息与本地变更却持续不可用。后台查询还会通过工作区比较执行仓库配置的辅助程序。

## 决策

Git 检查使用 Session 解析出的沙箱模式与子进程提供方。完全权限无需沙箱后端；受限模式保留强制约束，绝不以无沙箱方式重试。Session 统一决定文件系统权限，包括工作区写入权限。查询命令不请求修改仓库。

本地补丁与统计应用命令级 Git 配置以禁用 clean/process filter，不修改用户配置。环境项保留包含等号的子节名称。现有钩子、fsmonitor、外部 diff、textconv、可选锁与延迟获取限制继续生效；子模块查询展示提交变化，不扫描内部脏文件。配置读取失败时停止比较；变更视图区分过滤器配置失败与 diff 过大，并提供重试。这些限制参考 Codex 的信息展示型 diff，同时保留 DSH 对执行环境与取消过程的管理。

## 考虑过的替代方案

**所有查询强制只读。** 这让已明确取消限制的 Session 依赖不可用的后端。使用 Session 模式使工具与面板的权限行为一致。

**失败后无沙箱重试。** 这会静默授予受限 Session 原本没有的权限。

**运行已配置的内容转换器。** 它们可能在自动刷新时执行程序并写入文件。禁用它们以放弃转换后内容等价性为代价，换取可预测的查询行为。

## 后果

操作系统的写入保护跟随 Session 模式，而非独立的面板策略。禁用 clean/process filter 后，比较仍应用 Git 内置的换行、ident 与编码转换：已物化的 LFS 文件及其他过滤文件可能显示为变更，即使普通 Git 认为它们未变。仅保留指针的检出可正常比较。子模块内部未提交内容不显示。原 Forge 记录仍保留面板所有权与工作树生命周期的决策；本记录仅替代其无条件只读策略。

过滤器覆盖需要 Git 2.31 或更新版本；旧 Git 可能忽略覆盖，按 Session 权限执行已配置的辅助程序。枚举与 diff 在独立进程中执行，因此并发新增的驱动可能绕过覆盖。这些限制减少附带的辅助程序执行；所有实际运行进程的权限由 Session 沙箱决定。

真实仓库测试覆盖权限模式、沙箱不可用、索引与配置不变、辅助程序标记、子模块提交、过滤文件字节和过滤器枚举失败。Web 回放覆盖通过选择器切换权限及相应的检出信息与本地变更视图。
