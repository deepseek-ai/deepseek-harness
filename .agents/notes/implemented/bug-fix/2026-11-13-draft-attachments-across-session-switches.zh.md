# Agent Note：草稿附件跨会话切换

Status: implemented

[English](2026-11-13-draft-attachments-across-session-switches.md) | 中文

## 问题

切到另一个会话再切回时，输入框的附件栏被清空，文字却还在（issue #5070）。会话 scope 销毁时会释放退役输入框持有的全部附件并回收图片预览，之后没有任何途径能重建它们。

## 决策

**Conversation 服务在切换期间保留全部草稿附件。** `ConversationController` 记录每个草稿附件属于哪个会话。Host 接受消息时，这些附件立即退出会话归属，注册表则保留它们直到回显结算。退役的输入框只在其会话已被删除、或消息与命令已经提交时释放附件，因为客户端无法判断已提交的命令是否用掉了附件；被中止的斜杠行裁决会保留附件。其他情况下附件继续登记，进行中的上传继续进行，失败的上传保留原位重试，会话下一次挂载的输入框按附件栏顺序接回它们。没有挂载输入框时被删除的会话，由 hub 的会话目录监听释放其附件。选择或拖入的文件只占一个浏览器文件句柄；粘贴的图片会把字节保留在内存中，直到发送、移除或其会话被删除。

**刷新时提示被丢弃的附件，而不恢复它们。** `pagehide` 时，输入 hub 在浏览器存储中为每个仍持有草稿附件的会话写一个标记；往返缓存恢复页面时清除这些标记。挂载时有标记且没有已登记附件的输入框，会显示「请重新添加」提示。

## 考虑过的替代方案

**刷新后通过浏览器 durable 引用与 Host `restore` Remote 恢复附件。** 它能在页面刷新后找回已上传的文件和图片，但需要新增一个 Host Remote 及其 Liveshare 与目录分类、一种浏览器持久化格式、恢复期间的发送拦截和图片字节载荷。主要用户所在的桌面端收益很小：桌面端 Host 每次启动都绑定新端口，存储 origin 连同所有已存引用都无法跨应用重启保留。

**切换时释放已结算附件，切回时由 Host 恢复。** 它能在会话不显示期间省下粘贴图片的内存，但每次切回都需要一次 Host 往返，弱网下会失败，并且之后还要再分配同样的字节。

## 影响

切换会话从不访问 Host，因此弱网不会让草稿附件在切换中丢失。刷新或崩溃仍会丢弃附件；崩溃时不会写标记，因此没有提示。
