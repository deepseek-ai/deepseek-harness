# Agent Note：草稿附件跨会话切换

Status: implemented

[English](2026-11-13-draft-attachments-across-session-switches.md) | 中文

## 问题

切到另一个会话再切回时，输入框的附件栏被清空，文字却还在（issue #5070）。会话 scope 销毁时会释放退役输入框持有的全部附件并回收图片预览，之后没有任何途径能重建它们。

## 决策

**带附件的草稿持有其会话的作用域。** 输入框草稿有附件且其会话未被删除时，输入 hub 以不保留事件连接的 `draft` 引用持有该会话，见 [Session retain 子要素与最近访问会话](../architecture/2026-11-15-session-retain-facets-and-recent-views.zh.md)。因此切走以及从最近访问会话中被淘汰时，同一个输入框 shell 和其中的附件都会保留：进行中的上传继续进行，失败的上传保留原位重试，粘贴的图片把字节保留在内存中。移除最后一个附件、发送它或删除会话会释放这条引用；随后作用域销毁时释放草稿仍持有的全部附件。

**刷新时提示被丢弃的附件，而不恢复它们。** `pagehide` 时，输入 hub 在浏览器存储中为每个草稿持有附件的会话写一个标记；往返缓存恢复页面时清除这些标记。挂载时有标记的输入框会显示「请重新添加」提示。

## 考虑过的替代方案

**刷新后通过浏览器 durable 引用与 Host `restore` Remote 恢复附件。** 它能在页面刷新后找回已上传的文件和图片，但需要新增一个 Host Remote 及其 Liveshare 与目录分类、一种浏览器持久化格式、恢复期间的发送拦截和图片字节载荷。主要用户所在的桌面端收益很小：桌面端 Host 每次启动都绑定新端口，存储 origin 连同所有已存引用都无法跨应用重启保留。

**在 Conversation 服务中记录草稿附件归属，并在下一个输入框中接回。** 它不持有作用域也能保留附件，但要通过会话目录监听再跟踪一遍 Session 生命周期，并按输入框阶段拆分已提交附件的释放；持有作用域就能保住输入框本身。

**切换时释放已结算附件，切回时由 Host 恢复。** 它能在会话不显示期间省下粘贴图片的内存，但每次切回都需要一次 Host 往返，弱网下会失败，并且之后还要再分配同样的字节。

## 影响

切换会话从不访问 Host，因此弱网不会让草稿附件在切换中丢失。刷新或崩溃仍会丢弃附件；崩溃时不会写标记，因此没有提示。
