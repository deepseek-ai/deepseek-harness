# Agent Note: 将模型配置保留在子代理目录之外

Status: implemented

[English](2026-09-16-subagent-catalog-membership-only.md) | 中文

## 问题

父目录用于发现直接子级。记录子级创建时的 LLM provider 和 model，可以在不打开子级历史的情况下保留不可变配置，但发现与导航的消费者不读取这些值。创建配置也不能确定实际处理某次请求的模型。

## 决策

目录事件与投影保留子级身份、创建时间、模式和标签。`establishCatalogChild(parent, childHeader, descriptor)` 只接收发布成员关系所需的值。子级组合与请求历史各自保留模型配置；目录加载不增加子级观察或模型查询。

本决策仅替代[父目录决策](../architecture/2026-09-01-parent-owned-subagent-catalog.zh.md)中的创建模型元数据选择。该记录继续说明成功发布、事件顺序、fork 隔离和投影所有权。未发布的可选元数据声明及其专属预期输出不予保留；迁移基线中已有的历史 Session 世代保持完整。

## 考虑过的替代方案

**保留可选创建元数据，供未来展示使用。** 可选字段仍需要持久化 schema、缓存失效、写入方和回放预期输出。需要不可变创建路由的消费者可以证明这些成本合理，但当前消费者没有此需求。

**在发现过程中读取子级历史。** 这会增加与子级历史规模相关的工作，却不帮助确定成员关系。需要展示请求实际使用模型的功能，可以独立观察子级已有的 `modelSelection` 投影。

## 后果

目录不提供历史创建路由记录。重新引入此记录，需要存在无法通过已有子级组合或请求投影满足需求的消费者。初始读取、实时更新、重连和授权继续由现有模块负责。目录与创建测试、已记录 Session 回放以及两套 SDK 的预期输出验证了成员关系仍可在没有额外元数据的情况下发布。
