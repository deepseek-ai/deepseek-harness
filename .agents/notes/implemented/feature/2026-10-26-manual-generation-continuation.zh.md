# Agent Note: 手动继续生成

Status: implemented

[English](2026-10-26-manual-generation-continuation.md) | 中文

## 问题

模型请求失败后，用户需要再次请求，但不应插入人为构造的指令。浏览器分页可能缺少失败轮次起点，流式输出也不能反复复制历史。

## 决策

播放按钮通过现有 Session prompt API 提交 `content: []`。AgentLoop 保留带身份的 inbox 输入并启动正常闭合的新轮次，但不将空普通输入写成模型可见的 `user/message`。原失败轮次保持闭合。

Session API 拥有固定大小的 `conversationContinuation` 投影，向浏览器发布相同的值。准入要求失败符合条件、持有真正的空闲状态且没有待消费的用户输入。已接受的空输入将原先准入的工作带入新轮次，因此请求再次失败后仍保留继续资格。

六码手动白名单独立于提供方重试策略。非唤醒的注入上下文随请求进入。空输入被领取后，持久 inbox 回执仍支持 request-id 去重；不需要新增 Remote 操作或 Session 事件格式。

## 考虑过的替代方案

**本地化或隐藏的继续文本。** 增加模型可见指令并改变保留历史。

**单独的 resume 操作。** 现有 prompt 和 inbox 已可承载带身份的控制输入并拥有唤醒流程。

**保持失败轮次等待点击。** 改变失败结算、空闲状态、取消和模型选择语义。

## 后果

普通空草稿回车仍不执行。显式继续沿用提交状态与错误报告，不创建消息回显或生成草稿。pre-step 拒绝和被清空的批次仍阻止模型调用。

## 验证

单元和组装场景覆盖重复失败、请求去重、注入上下文、轮次闭合、工具结果保留、仅一条原始用户消息，以及客户端不读取完整事件窗口。
