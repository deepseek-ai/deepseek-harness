# Agent Note：单一宿主认领 LiveShare 房主状态

Status: implemented

[English](2026-11-11-liveshare-owner-state-host-claim.md) | 中文

## 问题

LiveShare 的房主状态——持久化的分享、它们持有的 Relay 注册、以及旁边记录的 fork——按宿主所在的 DSH home 寻址，而不是按服务它的进程寻址。在同一 home 上启动的第二个宿主会恢复同样的分享并把它们重新注册到 Liveshare 服务器，服务器随之把每条注册挪到新连接上。先前宿主的权限读取于是对着一条已被挪走的注册作答，围栏该分享，并连带停掉房主自己的回合。这份状态需要一个按目录命名、且不依赖各宿主自觉忽略彼此的归属者。

## 决定

`claimOwnerHost`（packages/experimental/liveshare/src/host/owner-host-claim.ts）在房主状态文件旁写 `owner-host.json`，记录服务它的进程。持有者恢复、注册并改动分享；其它宿主只加载记录，不发布任何东西。认领在挂载时只取一次：被后继者夺走的宿主会在下一次读取时发现，因为分享操作会重读该文件，而不是相信启动时取到的认领。丢失的认领会把每个会修改记录的 `liveshareShares` 操作变成类型化的拒绝 `liveshareShares/owner-state-held`，读操作保持可用，因此非持有宿主仍能向房主展示哪些内容被分享。它会导入凭据——那是它自己的登录——但不认领、也不重新注册任何东西。

规则沿用[会话写租约](2026-08-31-cross-process-session-write-lease.zh.md)确立的那套：所有权不设过期、竞争给出类型化回答而不是崩溃、进程已消失留下的记录会被收回。有三处不同，因为这个目录不是会话数据：

- **认领是建议性的，且它把关的是 Relay 注册而不是文件写入。** 状态文件自身的 registry 文件锁已防止并发写入丢掉持久条目，所以这条认领不保护任何分享数据或会话日志。它的全部目的是让一个进程在某一时刻独有服务器端的注册。
- **刻意没有过期时限。** 时限存在的意义是夺取卡住的持有者，而卡住的宿主在这里只持有自己的注册；夺取会让分享从第二条连接重新注册，而卡住的持有者仍相信自己拥有它们。因此停止服务的持有者会一直持有该状态，直到它的进程退出。
- **记录指向本进程时会被收回。** 同一进程内的所有宿主共享同一份房主状态，所以同一进程里的第二次挂载不能因为自己的 pid 而被挡在外面。

记录作为整份文件发布：先写到临时名，再硬链接到认领路径，于是该链接要么发布它所命名的记录，要么因已有认领而失败，任何读取方都看不到写了一半的认领。对活跃持有者认领会抛出 `OwnerHostClaimHeldError`；宿主报告该持有者的 pid 并在没有该状态的情况下继续，而不是启动失败。退出时最后才释放认领，即在 tunnel 与 worker 的注册停止之后，这样后继者不会在持有者仍在撤销注册时就开始注册同样的分享。

## 备选方案

**带过期、续期与夺取的租约**——分布式锁通常的形态，也是本仓库的会话写入用内核锁替换掉的那个。续期流量和夺取竞争在这里买不到任何东西：第二个所有者不会撕裂任何写入，卡住的持有者的唯一代价是它自己的分享服务到进程退出为止。

**什么都不做，让每个宿主都服务这些分享**——这正是那个缺陷：最后注册的宿主赢得注册，另一个宿主围栏该分享并停掉房主的回合，于是两个运行中的宿主会让房主自己的会话在无人要求的情况下停下。

**持进程终身的内核锁**——会话写租约自己的机制，崩溃后无需任何记录即可恢复。它无法向一个必须继续运行并服务读的宿主表达「该宿主已被后继者取代」；而且它只能以取锁失败来表达竞争，而不是给出一个房主能据以行动的 pid。记录同时也是后来的宿主用来告诉用户该停掉哪个进程的东西。

**活跃持有者存在时拒绝启动**——第二个宿主是查看本机分享了什么内容的正当方式，让它的挂载失败会把该 DSH home 其余部分的启动一起拖下水。

## 后果

同一 DSH home 上的两个宿主现在对每条分享只有一条权威的服务器注册，非持有宿主对修改类操作给出点名持有者的拒绝，而不是悄悄分叉。持有者死亡后，下一次宿主启动会释放该状态；在那之前状态不可达，这是不夺取卡住的持有者所刻意付出的代价。pid 复用可能把认领的持有者认错：下一个宿主于是没有这些分享地运行，直到那个无关进程退出或记录被移除，恢复时不会有任何东西丢失。认领不比较这个 DSH home 之外的任何东西，因此它仍是一个用户状态目录的建议性守卫，而不是多宿主授权服务——没有任何机制阻止一个指向其它 home 的宿主把同样的分享注册到服务器上。
