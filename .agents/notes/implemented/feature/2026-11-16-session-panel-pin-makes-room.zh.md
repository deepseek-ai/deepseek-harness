# Agent Note: 固定的会话面板让正文让出位置

Status: implemented

[English](2026-11-16-session-panel-pin-makes-room.md) | 中文

## Problem

[会话面板](2026-11-05-session-panel.zh.md)只在 348px 的末端留白里停靠。默认正文宽度下，这要求 Chat 外框宽 1576px，而左侧栏占去窗口 280px，因此约 1860px 以下的窗口都无法停靠面板。在 1440px、1512px 和 1728px 的窗口里，面板只能以浮层显示，在面板外按下指针就会关闭。想在工作时一直看到运行中的子智能体、后台任务或变更请求的用户，在这些宽度下无法让面板保持打开。停靠偏好帮不上忙：它只决定面板在已有空间的地方是否显示。

## Decision

面板带一个图钉：位于面板顶部末端角的切换按钮，所有会话共用一个偏好，存放在 `localStorage` 的 `dsh.sessionPanel.held` 中，默认关闭。图钉和停靠偏好都开启、且留白窄于 348px 时，Conversation 主体空出这段留白。正文列和输入框保持各自宽度，向起始边缘移动所缺的留白；正文列距起始边缘只剩 32px 后，改为变窄。面板随即停靠，按 Esc 或在面板外按下指针都不会隐藏它。如果让位会使正文列窄于 480px，也就是 Chat 外框窄于 860px，主体不让位；此时已固定的面板与未固定时相同，直到外框再次够宽。未固定的面板行为不变。

### 位置归主体所有，面板提出申请

[`ui-conversation`](../../../../packages/client/ui-conversation/README.zh.md#end-reserve) 拥有正文的宽度轴、滚动容器和宽度手柄，因此这段位置也归它所有。样式表在 Conversation 主体上设置 `--dsh-chat-end-reserve` 来提出申请；主体据此推出滚动容器的末端内边距 `--dsh-chat-end-inset`，以及让正文列保持 480px 时能给出的最大预留 `--dsh-chat-end-reserve-max`。面板的样式表通过一条 `:has()` 规则把预留设为 348px，该规则在留白探针带有标记时匹配，因此申请不需要 Slot 属性，也不会让 Chat 视图重新渲染。

主体从滚动容器的宽度推出这些长度；它测量该宽度并发布为 `--dsh-conversation-viewport-width`。有三个盒子读取内边距：滚动容器用它作内边距，主体中的宽度手柄用它定位，[`ui-chat`](../../../../packages/client/ui-chat/README.zh.md#scroll-ownership) 的侧边层用它越过内边距延伸回去，让面板位于滚动容器的末端边缘。用百分比写出的长度在这三处会按不同的盒子解析，而滚动容器自身的内容盒又随内边距变化。测量得到的像素宽度让三处取得同一个值，并且不随内边距改变。

### 两个不依赖图钉的探针

面板通过 1px 的探针报告两项事实：正文不动时留白放得下面板，以及正文能让出这段位置。侧边层发布的留白包含内边距，留白探针再把它减掉，因此正文让出的留白不算作留白。插件把这两项事实与图钉结合：留白放得下面板，或者图钉已开启且正文能让位时，面板可以停靠。

两项事实都不依赖图钉，插件因此在按下之前就掌握所需信息。只有固定后能停靠时，它才在浮层上提供图钉。用户取消固定一个仅靠图钉留在正文旁的面板时，它知道面板即将失去位置，于是让面板保持打开并变为浮层，而不是在指针下把它移走。正文让出的位置不会改变提出让位的那项判断，布局因此不会来回振荡。

### 图钉与停靠偏好保持独立

标题栏开关仍然通过切换停靠偏好来隐藏和显示已固定的面板，隐藏后让出的位置还给正文。固定面板同时会开启停靠偏好，因为固定面板的用户希望它显示出来。停靠偏好沿用 `localStorage` 键 `dsh.sessionPanel.pinned`，已保存的选择得以保留；插件状态中把它称为 `docks`，把图钉称为 `pinned`。

## Alternatives considered

- **固定的面板盖在正文上。** 不需要改动布局，但在 1440px 的窗口里，只要面板处于固定状态，就会一直遮住正文列约 83px 以及每条消息末尾的操作按钮。整个会话期间都打开的面板不能遮住每条回复的一部分。
- **面板一显示就让位。** 这会在用户没有要求的情况下，改变笔记本宽度下所有用户的正文位置和宽度。[面板自身的决策](2026-11-05-session-panel.zh.md)默认不动正文，图钉把这项取舍交给用户选择。
- **通过 Slot 属性传递测量出的预留值。** Conversation 主体、Chat 视图和侧边层都要为这一个使用方转发回调，预留值每次变化还会让 Chat 视图重新渲染。自定义属性两者都不需要。
- **只用百分比，不发布宽度。** 内边距在滚动容器、宽度手柄和侧边层中会取得不同的值，而判断能否保留 480px 正文列时读到的宽度又会被内边距本身收窄。
- **一个探针，规则随图钉变化。** 插件将无法知道未固定的浮层能否固定，也无法知道取消固定后面板是否还有位置。
- **正文让位期间保留宽度手柄。** 手柄位于居中正文列的两侧，拖动时正文列以中心为基准变宽。正文列的末端边缘被预留固定后，拖动只会移动起始边缘，速度是指针的两倍。手柄在正文重新居中之前不显示。
- **在嵌入的 Chat 视图中让位。** 嵌入的正文宽度是其外框的百分比，内边距需要该外框自己的测量值，而嵌入的外框很少有 860px 宽。嵌入的 Chat 视图不让位。

## Consequences

- 用户可以在笔记本宽度下把面板留在正文旁。在侧栏展开的 1440px 窗口里，742px 的正文列宽度不变，向起始方向移动 143px；在 1280px 的窗口里，正文列收窄到 613px。
- Chat 外框窄于 860px 时图钉不起作用，面板仍是原来的浮层。
- 正文让位期间不显示宽度手柄；用户需要取消固定或隐藏面板后再拖动宽度。
- `ui-conversation` 发布滚动容器的宽度和两个推出的长度，并给滚动容器的末端加内边距；`ui-chat` 的侧边层多了末端外边距，其留白包含内边距。两者都没有为此增加渲染或观察。
- 每个已挂载的面板观察两个探针而不是一个；两者都只在判断翻转时回调。

## Testing

单元测试读取三份样式表，并在边界附近计算预留、内边距、留白和两个探针的取值。`apps/web/tests/session-panel-layout.e2e.ts` 在随产品发布的 Web 组合中测量：固定、收窄到 480px 正文列、越过该边界、刷新页面、用开关隐藏以及取消固定时的正文列、输入框、宽度手柄、探针、面板和图钉。
