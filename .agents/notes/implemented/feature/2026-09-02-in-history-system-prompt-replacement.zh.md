# Agent Note: 历史内系统提示词更新

Status: implemented

[English](2026-09-02-in-history-system-prompt-replacement.md) | 中文

## 问题

计划指导、工具、persona 或模型变量变化时重写开头提示词，会从第一个 token 起使提供方前缀失效。后续指令消息可以保留此前的对话前缀，但其表示取决于模型能力。[表面节点决策](../architecture/2026-09-02-system-prompt-as-surface-node.zh.md)让其原始位置持久保存。

## 决策

保留缓存的选择保持不变：在指令进入对话时记录它们，而非例行移到对话开头。[按段更新](../architecture/2026-10-21-section-based-system-updates.zh.md)取代了原先按路由限制的整份提示词规则。它在所有路由上追加变化的来源文本与显式通知；循环不会把最新系统消息视为整份提示词，也不会因为不支持原生更新而合并。[压缩](../architecture/2026-11-09-deferred-system-compaction.zh.md)提供显式合并时机，而[未变指令的新序列](../bug-fix/2026-10-22-series-start-unchanged-prompt-prefix.zh.md)保留既有指令位置。

`systemPromptUpdate = 'in-history'` 仍是解析后模型信息和已准备调用声明的模型能力，并记录在请求上下文中。目录校验该值；模型名称或协议族不隐含支持。此声明描述原生表示，而非是否允许准入分段增量。适配器通过原生消息、合并系统字段或 [pi-ai 提醒回退](../architecture/2026-10-19-pi-ai-system-reminder-fallback.zh.md)保留全部指令。实际绑定的已准备调用决定序列化，而非此前的请求上下文快照。

指令和用户提交发生在开放步骤内，成功完成请求中间件及准备之后。取消任一准备阶段都会使其保持未提交。新指令位于新准入用户之前。重试不重跑组装、步骤前选择或用户准入；压缩后，下一次尝试根据同一批已捕获段重建指令。恢复保留已提交指令并追加变化，因为进程重启本身不必使提供方缓存失效。

### 展示与计量

Chat 将后续非空系统节点显示为折叠的更新卡片，避免在同一步骤的请求头中重复。Trajectory 可将它表示为合成的请求头事实。请求头配置和工具独立于指令变化；只比较真实请求头会漏掉中间的系统更新。若已加载窗口没有更早的系统节点，该节点显示为初始提示词。面向人的 transcript（文本记录）省略系统消息。

请求提示词检查使用按存活对话位置排序的不可变前缀状态，而非仅依赖事件序号或来源引用。头节点重写可以在更靠后位置的更新之后才记入日志；替换可以移除系统节点。空节点保持可寻址，不会抹去其他保留文本。当替换端点早于已知窗口且其位置未知时，检查会隐藏后续提示词文本，直到向前补载重放解析缺失前缀。数字事件顺序无法安全猜测位置。历史卡片保留各自的前缀状态。

Token 构成将每条存活系统消息计入系统 token。[紧凑计量状态](../architecture/2026-10-13-context-breakdown-system-prompt-state.zh.md)保留系统节点和运行总量，而非逐消息计量条目。提供方的 `cacheReadTokens` 仍是可观察的缓存信号；增量准入和原生支持元数据都不保证缓存命中。

## 考虑过的替代方案

**按路由限制的整份提示词替换。** 原设计把最新系统消息视为完整提示词，并据此拒绝分段增量。规范的逐来源记录与显式替换或退役通知让新增内容无需该解释即可成立；适配器回退在其他路由保留这些内容。因此，原先的新序列和不支持路由合并规则并非当前行为。

**部署开关取代原生能力声明。** 开关可能错误描述选定模型能接受的内容。即使能力不再限制分段准入，它仍由模型负责声明。

**始终追加，或在每次新序列或恢复时合并。** 无限追加会保留陈旧头文本并占用上下文；压缩提供合并。局部替换可以保留大部分有效前缀，重启也可以保留热的提供方缓存，因此两者本身都不足以移动指令。模型切换同样无需在已记录路由变化之外增加特殊合并规则。

**在步骤前处理与请求准备之前提交，或将更新放在新用户之后。** 提前提交可能准入已取消内容，或漏掉移除了更新所比较指令的压缩。将更新放在用户之后会颠倒既有的指令先于输入顺序。捕获可以更早发生，但比较和提交必须晚于任何压缩并早于请求派生。

**用此前请求上下文决定当前表示。** 它描述前一次调用，对首次调用、恢复的 Session 或路由变化可能不适用。实际绑定的适配器负责当前序列化。

**合并时只清除最新系统节点。** 更早的指令仍会保留，并可能重新生效。重建先清除保留的新增内容，再替换初始头节点，保留中间对话。

**只保留标量计量总量。** 替换价格无法识别消失了哪些系统节点。仅保留这些节点并使用影子价格元数据，无需逐消息检查点即可分类。

## 影响

追加更新可能保留提供方前缀，但每项保留更新在合并或移除前都会消耗输入 token。频繁变化的事实仍更适合运行时上下文。将指令展平的适配器可能使开头提示词失效，而用户角色提醒不会获得系统权限。重写或重排消息的代理也可能破坏预期指令顺序或缓存复用。

## 验证

循环和请求重建测试覆盖路由变化、恢复、取消、固定重试组装、压缩后重建及不变前缀。客户端测试覆盖更新卡片、请求头去重、历史前缀检查及历史不完整时的隐藏。计量测试覆盖保留系统节点、替换和重放。TypeScript 与 Python SDK 的预期输出包含追加的类型化系统事件，无需密钥的已记录 Session 则固定对话顺序中的指令。真实 API 适配器覆盖使用 `DEEPSEEK_IN_HISTORY_MODEL` 检查模型遵从追加更新，并比较它与重写开头提示词的提供方缓存复用；未配置时跳过。这些真实提供方检查仍有必要，因为元数据不能证明模型行为。
