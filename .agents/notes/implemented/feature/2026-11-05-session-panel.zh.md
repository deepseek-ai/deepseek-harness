# Agent Note: 停靠在 Chat 视图末端留白的会话面板

Status: implemented

[English](2026-11-05-session-panel.md) | 中文

## Problem

与当前会话相关的信息（项目目录、它开出的变更请求，以及之后的产物）没有统一的位置。各自的拥有者分别加会话标题栏按钮，内容一多就再开一个右侧栏标签页，forge 的变更请求就是这样一个标签页。侧栏标签页显示时占用正文宽度，一次只显示一个，而且每条消息之外都要多点一次才能看到。需要的界面是：可以放在对话旁边常驻而不遮挡正文；多个插件各自填充；没有空间时自动隐藏；用户可以从会话标题栏显示或隐藏。

## Decision

[`dsh-client-ui-session-panel`](../../../../packages/client/ui-session-panel/README.zh.md) 新增一个会话标题栏开关（`conversation.session.header.utilities`，order −10）和一块悬浮面板，面板占用 `conversation.chat.aside`：这是 [`ui-chat`](../../../../packages/client/ui-chat/README.zh.md#scroll-ownership) 在 Chat 视图中、轮次轨道旁渲染的 slot。侧边层是 Chat 外框顶部的零高度图层，与轮次轨道一样在共享滚动容器内 sticky 定位：面板不随正文滚动，继承滚动容器的输入框区域与视口高度，也不需要 Conversation 外壳提供落位。Chat 以外的视图不显示面板。

### 停靠取决于正文留白

只有正文列到 Chat 外框末端边缘的留白放得下面板时才停靠（344px：与正文列及其宽度拖拽条保持 48px，最小宽度 280px，外加 16px 边距）。判断依据是留白而不是视口宽度，因为正文列宽度可自适应、可由用户拖拽，右侧栏也会占用框架宽度：同一个视口可能只剩 75px，也可能有 600px。Chat 视图持有外框和正文列，因此由它根据 `ResizeObserver` 报告的两者宽度算出留白，并作为 owner 属性 `endGutter` 交给侧边层的占位组件。

每个已挂载的面板把自己的留白上报到插件状态中，开关读取为其会话上报的最宽留白；没有上报的会话表示没有 Chat 视图在显示它。开关和面板用同一个纯函数决定呈现方式，因此开关能如实报告 `aria-expanded`，也知道按下后是切换停靠还是打开浮层；纯 CSS 的容器查询无法把结果告诉 Chat 视图之外的元素。没有 Chat 视图显示该会话时（例如在轨迹视图中），开关不可用，悬停提示请用户切到「对话」视图；`ui-conversation` 把视图选择留在其外壳内部，因此开关不自行切换视图。

停靠遵循所有会话共用的一个持久化偏好，默认开启。没有空间时，按下开关会为该会话在正文上方打开临时浮层；它从不改变偏好；该会话的留白可以停靠面板，或不再有 Chat 视图显示该会话时，浮层关闭，因此不会自己重新出现。面板状态跟随打开浮层的会话所上报的留白。面板卸载或其 Chat 视图换到另一个会话时撤回上报；撤回放在与留白更新分开的 layout effect 清理中，因此留白变化永远不会被当成卸载。自动隐藏加按需浮层，既保证正文不被遮挡，也让笔记本宽度下的信息依然可达。

### 分栏是注册项；面板绘制标题

每个分栏是一次 list 注册，带 `id`、`order` 和必填的 `label`。面板把实时注册投影成标题并逐个绘制，再用 `renderSlot(..., { only: id })` 渲染分栏正文；CSS `:has()` 规则隐藏正文没有渲染内容的分栏，因此分栏不渲染任何内容即可退出，不需要 effect 向拥有者上报可见性。标题尾部控件是以分栏 `id` 为键的 keyed slot；多个插件共用的分栏声明自己的行 slot，内置「环境」分栏就以 `conversation.session.panel.environment.row` 这样做。面板隐藏时也要可见的标记放进开关上的角标列表。

所有贡献方的行都使用 `PanelRow` 原语，使不同包的图标、文字与尾部区域对齐；功能包之间不能共享各自的行组件。

### 轮次轨道位于起始边

轮次轨道连同刻度、焦点环和预览位于滚动容器的起始边，末端留白留给停靠面板；它的 900px 隐藏规则保证旁边有足够空间容纳起始侧的宽度拖拽条。

## Alternatives considered

- **落位在 `conversation.content`。** 已否决：这种做法让 `ui-conversation` 在宽度拖拽条旁、滚动容器之外渲染面板，由宽度控件把留白测量结果写入按会话划分的 `ctx.uiConversation.layouts` source，并把输入框区域与视口高度变量从滚动容器挪到正文容器上，使落位能读到它们。Conversation 外壳因此要为单个功能承担几何测量和变量位置；而不随滚动的界面元素可以像轮次轨道那样在滚动容器内 sticky 定位，要测量的正文列也本来就归 Chat 视图所有。
- **右侧栏标签页。** 变更请求已有这种实现，但它显示时会压窄正文，一次只显示一个标签页，而且 [UI 指南](../../../skills/dsh-client-ui-ux/SKILL.md#reuse-before-adding)把侧栏留给按需打开的内容，而不是常驻摘要。
- **dock kit 的悬浮窗。** `FloatLayer` 窗口可拖拽、可缩放、按视口坐标定位；锚定在正文留白的摘要用不上这些能力，还要对抗窗口自身的定位规则。
- **按视口宽度断点。** 正文宽度自适应、可拖拽，右侧栏占用可变宽度，视口断点要么遮挡正文，要么在空间充足时也隐藏面板。
- **纯 CSS 隐藏加点击时读取。** 对留白做容器查询可以隐藏停靠面板，开关在按下时读取计算结果，与后台任务按钮的做法相同。但开关渲染时仍不知道面板是否显示，偏好为停靠而留白不足时，`aria-expanded` 与提示文字都会出错。
- **挤压正文腾出空间。** 在笔记本宽度下把正文列移开来停靠，会改变居中的正文列、composer 和两侧宽度拖拽条；这仍是另一项布局决策。
- **会话作用域标准 hook。** 给每个会话作用域 Slot 增加一个留白 hook，会让客户端所有组件测试夹具都要补上它；留白只有两个读取方：面板通过 owner 属性读取，开关通过插件自己的状态读取。

## Consequences

- 在默认正文宽度下，对话区要约 1608px 宽才能停靠，因此笔记本宽度使用浮层；除非用户主动打开，面板不会遮挡正文。
- 独立插件的分栏共享同一界面、排序和标题样式，彼此不依赖；已占用的分栏 id 可以被更高优先级的注册替换。
- `ui-chat` 多了一个 slot，每个 Chat 视图多一个 `ResizeObserver`；`ui-conversation` 没有改动。
- 面板只出现在 Chat 视图中；其他视图下开关仍在标题栏中，但不可用。每个 Chat 视图实例都会渲染侧边层，因此同一会话同时显示在主正文区和嵌入的对话中时，两处都会显示浮层。
- 轮次轨道的位置对所有用户都变了；行为和隐藏规则不变。
- 变更请求、后台任务和子智能体成为分栏，取代变更请求侧边栏标签页、其起始页入口，以及标题栏中的后台任务和子智能体控件；标题栏仍为子会话保留子智能体面包屑切换器。分栏只在面板显示时挂载，因此需要在隐藏面板后保留的状态（例如已清空的任务行）放在按会话划分的 slot store 中。
