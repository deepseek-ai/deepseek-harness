# Agent Note: 拒绝静默的空 catch 子句

Status: implemented

[English](2026-09-21-reject-silent-empty-catch.md) | 中文

## 问题

空 `catch` 会丢弃其 `try` 的所有失败，包括作者未预料到的缺陷。根规则要求此类子句命名错误、说明丢弃该错误为何安全，并将其 `try` 限制为一条语句，使子句只丢弃作者考虑过的失败。没有检查时，新增子句逐渐偏离该规则，而违反规则的现有子句分布在许多互不相关的包和测试所属模块中。

## 决策

[检查器](../../../../scripts/verify-empty-catch.ts)通过 `pnpm run verify-empty-catch` 运行，使用 TypeScript 语法树解析第一方 JavaScript 和 TypeScript，并报告未命名、未说明原因或包裹多语句 `try` 的空子句；空子句指主体中除 `;` 外不含任何语句的子句。单独的 `_` 视为未命名；lint 要求未使用的绑定以 `_` 开头，因此 `_alreadyGone` 这类符合要求的名称可以说明预期的失败。主体含有其他语句的子句不属于此规则的范围，因为语法无法表明它是否处理了错误。检查器确认形式；审查依据 [dsh-error-handling](../../../skills/dsh-error-handling/SKILL.md#empty-catch-clauses) 中的指引确认名称和原因属实。

现有子句使用精确基线记录，键由仓库相对路径、子句语法 token 连同其违反条件的 SHA-256 摘要及出现次数组成。摘要包含违反条件，因此把已记录的单语句 `try` 扩大为多语句 `try`，或删除已记录的原因，都会产生新的检查发现；而在 `try` 内部进行不改变其违反条件的修改，不改变子句的标识。基线沿用 [unknown 类型断言清单](2026-09-19-no-unknown-casts.zh.md)的做法，两个检查器共用[清单模块](../../../../scripts/baseline-inventory.ts)：基线修改只能删除条目或减少次数，`--prune` 删除已失效的条目并在存在新发现时拒绝写入，且没有任何命令可以添加放行。unknown 类型断言清单要求先解决断言，才能将其移至未登记的文件；与之不同，移动包含已记录子句的文件时，须在同一变更中重命名其基线键，因为收窄已记录的 `try` 由其所属模块负责，而不属于移动文件的变更。

检查器在[门禁运行器](../../../../scripts/run-gates.ts)的 `hygiene` 和 `check-all` 配置以及 CI 静态模式和主模式中运行。`.catch(() => {})` 等空的 Promise 拒绝处理函数不属于此规则，另由 issue #8033 跟踪。

## 考虑过的替代方案

**先修复所有现有子句，再执行规则。** 不采用，因为收窄多语句 `try` 会改变子句丢弃哪些失败，只有各所属模块才能判断。基线使规则可以立即开始执行，同时现有子句仍作为已记录的检查发现，由其所属模块修复。

**对整个 `try` 语句计算指纹。** 不采用，因为已记录 `try` 内部的每次修改都会产生新的检查发现，迫使所属模块在无关工作中修复该子句。对子句连同其违反条件计算指纹，可以拒绝已记录子句上新增的违反条件，同时不让子句的标识依赖 `try` 内部的语句；已经过宽的 `try` 可以增加语句而不产生新的检查发现。

**提供从指定修订版本记录子句的命令。** 不采用，因为本地命令无法证明该修订版本就是目标分支：指定当前分支会记录该分支自身的子句。目标分支包含检查器后，合并目标分支会一并带入其基线，因此不需要这样的命令。

**在文本中搜索 `catch {}`。** 不采用，因为注释、字符串、空白和绑定模式都会使文本模式失效，而且规则的条件依赖语法树。

## 影响

新增和修改的空子句必须符合规则，修复已记录的子句时须清理其基线条目。部分修复，例如添加名称但 `try` 仍然过宽，会改变子句的标识，因此检查失败；所属模块须先完整修复子句，再清理基线条目。基线键不含行号，因此已记录的子句可以在所在文件内移动；同一文件中相同的子句共用一个指纹，其计数涵盖其中每一个子句。

通过检查器说明每个未记录的空子句都符合规定形式。它不证明原因属实，不证明非空处理代码处理了其错误，也不证明包含一个代码块或复合语句的 `try` 只丢弃一个操作的失败。
