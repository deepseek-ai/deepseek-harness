# Agent Note：MCP 连接器账号接入连接器账号注册表

Status: implemented

[English](2026-11-08-mcp-connector-accounts.md) | 中文

## 问题

Linear、Notion、腾讯文档等连接器插件在 Host 上向 MCP 管理器注册 OAuth MCP 服务器，并在插件页显示其账号。管理器已经持有授权尝试、grant 和服务器状态，各连接器的状态、按钮和 23 条文案都相同。[连接器账号注册表](2026-11-06-connector-account-registry.zh.md)根据 Host 上的来源和展示函数显示每个账号，因此 MCP 需要一个适配，把管理器对服务器的视图转换为这样的来源和展示函数。

## 决定

[`@deepseek-ai/dsh-mcp-account`](../../../../packages/mcp/mcp-account/README.zh.md) 提供 `ctx.mcpAccounts`。连接器的 Host 行注册其服务器名、插件包以及点出服务名称的文案；该服务以 `mcp:<server>` 为键，把账号注册到 `ctx.connectorAccounts`。

| 部分 | 选择 |
|---|---|
| 来源 | 读取管理器 `list()` 中该服务器的条目，并观察 `mcp-manager/status`；`refresh` 什么也不做，因为管理器会发布每次变化 |
| 操作 | 进行中的授权尝试就是操作，其 id 就是操作的 id，因此发起它的浏览器跟随的是管理器自己的尝试；结束的尝试就是结果 |
| 页面操作 | `connect` 发起授权，已连接时也可用，用户不必先删除授权就能更换账号或工作区；`sign-out` 和 `retry` 通过管理器退出登录、重启服务器，结束后报告各自的结果 |
| 阶段 | 等待浏览器和授权中属于连接中；需要重新授权的服务器属于未连接，原因写在说明里；已关闭、等待凭据、已停用或失败的服务器属于不可用，只有重启能恢复时才提供“重试” |
| 文案 | 各连接器共用的 23 条文案是 Host 上 8 种语言的字典；每个连接器只提供点出其服务名称的文案 |

管理器的 `startAuthorization`、`cancelAuthorization` 和 `signOut` 是不带 Remote 的 Host 方法，因此浏览器不会指定要授权的服务器。

## 考虑过的替代方案

**管理器的授权操作继续走它的 Remote。** 否决：页面要传入 Host 已经知道的服务器名，而且会有两条路径发起同一次尝试。

**为每次授权维护适配自己的操作。** 否决：管理器已经记录尝试的 id、阶段和授权页，第二套记录只会重复它。注册表允许来源在管理器创建尝试后再回答 `start`。

**以插件包作为连接器账号的键。** 否决：服务器名在 MCP 账号中唯一，因此这个键也会拒绝同一服务器的第二个账号；没有插件包的、在 Settings 中配置的服务器也使用同样的键。

## 影响

连接器不提供任何浏览器代码和页面规则，由共用的页面渲染其账号。需要重新连接的账号显示为未连接，不再单独使用警示色，其状态和说明会点出原因。每个浏览器跟随同一条注册表流，Host 通过管理器的状态事件跟随管理器。
