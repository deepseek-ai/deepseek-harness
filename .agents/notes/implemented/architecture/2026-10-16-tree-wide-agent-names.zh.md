# Agent Note: 树内唯一 agent 名字

Status: implemented

[English](2026-10-16-tree-wide-agent-names.md) | 中文

## 问题

Session id 提供持久执行身份，但模型协作时难以阅读。描述可以重复，不能标识接收方。用户要求 subagent 和 teammate 显式使用唯一名字，并为根保留 `lead`。

## 决策

持久化与授权保留 Session id。模型工具接受整棵 agent 树内唯一且不可变的名字。根 catalog 记录全部已提交分配：带名字的直接子级事实，或仅登记后代名字的事实。已有 catalog 投影拥有两者，其 wire 视图仍用于直接子级发现。本地 descriptor 携带子级自身名字。根级运行时 Set 仅保存临时预留；已提交名字在执行结束和重启后仍然保留。

本决策取代 [Agent Teams 作为 subagent](2026-10-15-agent-teams-as-subagents.zh.md) 中不使用名字的接口。谱系权限与共享子代理生命周期保持不变。名字解析不授予消息、中断或任务分配权限。旧的无名后代获得稳定的 `legacy:<session-id>` 地址；Team 分配任务也接受活跃历史成员的此类地址。

## 考虑过的替代方案

**父级内唯一的名字。** 发现后代时需要限定路径。整棵树共享一个命名空间，使每个调用方使用相同地址。

**可回收的名字。** 原 agent 结束后复用名字，可能改变排队或延迟工作的接收方。保留分配使接收方身份稳定。

**独立的根级分配事件。** catalog 的一个变体即可表达登记，无需另一种事件或投影。根登记避免普通名字检查遍历历史后代。代价是嵌套子级需要第二次同步追加：根登记失败后，父级发现事实可能残留。发现与冷恢复在接受此类命名子级前检查根登记。

## 影响

创建必须提供名字，分发前拒绝重名。独立根可以复用名字。工具结果、子级初始指引、消息前缀与结束通知使用名字。内部 Session 和任务负责人 id 保持稳定。[升级指南](../../../../docs/upgrade-guide/v0.2.1-alpha.4/agent-team-subagents/guide.zh.md)列出变化的工具参数与结果。

## 测试

命名测试覆盖并发重名拒绝、启动失败释放、嵌套树唯一性、独立根、根登记恢复、第二次写入失败、不可读历史分支、重复子级身份、无效持久化分配与旧地址查找。Headless 和 SDK 录制会话覆盖创建、消息、列表与完成通知；Team 测试保留历史任务分配，同时拒绝消息权限。
