# Agent Note: 插件 CLI 通过运行时上下文给出绝对路径

Status: implemented

[English](2026-10-27-plugin-cli-absolute-paths.md) | 中文

## Problem

飞书、企业微信、钉钉、腾讯会议等 CLI 应用插件把厂商 CLI 装在 PATH 之外。上游指南、CLI 自己的提示信息，以及钉钉和企业微信 skill 里的脚本，都按名称调用 CLI。模型必须运行插件安装的那一份，而不是别的安装或者找不到，同时 harness 不应为此改变模型命令的运行方式。

## Decision

每个应用插件把 CLI 的绝对路径注册到 [`@deepseek-ai/dsh-cli-account`](../../../../packages/connector/cli-account/README.zh.md) 的 Service `ctx.cliAccounts`。这个 Service 在 `PLUGIN_CLIS` 上下文顺序处注册一条必需、不做变量插值的运行时上下文，让模型按这个路径运行 CLI。skill 里的脚本按名称调用 CLI 时（钉钉和企业微信属于这种情况），这条上下文还让模型只在运行这些脚本的命令前加上 `PATH="<目录>:$PATH"`，并且不要导出 PATH，也不要按名称运行 CLI。在 Windows 上，内置组合挂载 `tool-pwsh` 而不是 `tool-bash`，文本改用 PowerShell 语法：调用运算符 `& '<路径>'`，以及前缀 `$env:PATH = '<目录>;' + $env:PATH`。skill 让模型使用当前运行时上下文给出的路径。插件自己的登录、状态和登出命令通过这个 Service 的命令执行器启动同一路径。

harness 不改变任何命令的环境：Bash、PowerShell、沙箱、持久终端和 hook 的运行方式与没有这些插件时相同。腾讯会议直接注册各平台的可执行文件 `dist/tmeet-<平台>`。钉钉的上下文在 dws 和钉钉 skill 安装完成前不贡献任何内容。加载时不检查命令是否在 Host 上运行；组合把命令放到 SSH 远端运行时，命令在访问不存在的路径时失败。

## Alternatives considered

**私有 PATH。** Shell 执行器和插件后端把各插件的 bin 目录放到 PATH 最前面，再由一段系统提示词列出插件 CLI。这需要在每个 shell 请求里加路径前缀、为后端命令准备环境、检查 runtime 是否在 Host 上，并为腾讯会议建一个 `tmeet` 符号链接。持久终端和 hook 拿不到这个前缀，而且它会遮住用户自己安装的同名 CLI。

**把路径写进 skill 正文。** 模型要加载 skill 之后才看得到正文，压缩可能把正文缩成摘要，升级之后历史里留的还是旧路径。静态的 skill 文件也要改成运行时生成。

**一个共享注册表、合成一条上下文。** 改造 shell-env 或为此新建一个包，可以只写一次规则，但要为四个调用方增加一个服务及其文档。工作目录、沙箱策略等其他运行时上下文都由掌握该事实的包自己注册；每个插件各一条，只是重复一句话。

**检查是否在 Host 上。** 发布的 profile 总在 Host 上运行命令。这个检查只会把 SSH 组合的失败从首次使用提前到加载，代价是 subprocess 和 shell 服务上多一个 `runsOnHost` 成员。

**按名称调用失败后追加提示。** 命令找不到已注册的名称时在工具结果里追加路径，可以在失败后纠正模型，但目前没有证据表明仅靠上下文文字不够。

## Consequences

把名称换成路径的是模型，不再是 PATH。按 2026-10-23 的统计，上游指南按名称调用 CLI 的行数为：钉钉 3,004 行、飞书 2,542 行、企业微信 321 行、腾讯会议 248 行；钉钉还有 33 个脚本按名称调用 `dws`。仍用名称的命令会运行 PATH 解析到的那份安装，或者因为找不到而失败；没有任何机制改写它。脚本那句话之所以禁止导出 PATH 和按名称运行 CLI，是因为在真实模型的运行中，只要求给脚本命令加前缀的写法会让模型先导出 PATH、再按名称运行 CLI。审批详情、工具卡和任务列表显示完整路径。

用户自己安装的同名 CLI 不再被遮住，持久终端和 hook 也不需要处理 PATH。运行时上下文不进入缓存的系统提示词，压缩后会重新提交；安装、启用或停用插件时追加一份运行时上下文快照。文字的写法按 Host 平台选择，判断条件与组合选择 shell 工具的条件相同；因此某个平台上的组合如果挂载了另一种 shell，得到的写法就不对。

kit 的单元测试固定了文字、必需状态、路径原样保留、就绪条件和释放时移除；每个插件的录制会话快照固定了它渲染出的上下文。
