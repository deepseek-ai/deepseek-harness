# Agent Note: Session workspace root

Status: implemented

[English](2026-11-03-session-workspace-root.md) | 中文

## Problem

进入 Git 工作树的 Session 只记录了当前目录的变化。同一事件也记录普通的 `cd` 进入子目录，因此消费方无法区分移动的光标与换掉的检出目录：文件视图、变更摘要或写边界要么跟随每次 `cd`，要么停留在原始项目上。header 只记录原始项目这一个目录，而直接在链接工作树内打开的 Session 不记录它所在的检出目录。支持在一段对话内进入另一个检出目录的同类产品都保留不可变的会话起点，把每次迁移记录为事件，并把 shell 光标与它所在的检出目录区分开。

## Decision

每个 Session 有三个目录，各有一个所有者。`header.cwd` 仍是不可变的原始项目：Session 身份、工作区分组和恢复目的地。`dsh-working-directory` 拥有另外两个。当前目录是相对路径解析的光标；它的 `workingDirectory` 投影与 `set` 不变。工作区根是该光标所在的检出目录；`workspaceRoot` 投影从同样的 `working-directory/change` 事件折叠出它，取包含当前目录的最长已登记锚。锚是原始项目以及 `relocate(agent, root, { cwd? })` 进入过的每个检出目录。

`relocate` 验证根及其内部的目录，然后提交一条可选 `anchor` 指向该根的 `working-directory/change`。根内部的 `set` 只移动光标；进入另一个锚的 `set` 把该锚选为根；所有锚之外的 `set` 移动光标并保留根。恢复到原始项目时再次把它选为根。事件的可选属性是一次同版本持久化变更，记录在[确认记录](../../../../docs/persistence-changes/2026-11-03-working-directory-anchor.zh.md)中；没有 `anchor` 的日志折叠后以原始项目为唯一的锚。

工作树创建通过 `relocate` 进入检出目录；离开它就是既有的 `set` 回到原始项目，锚规则将其变为根的变化。子代理在 header 中保留父级的原始项目；当父级的根是另一个检出目录且子级在其中启动时，子级迁入该根，因此子级的根与父级一致。光标与根不同时，用户上下文快照增加一行 `Workspace root`，选中另一个根的变更在通知末尾给出新根。SDK 的工作目录方法返回 `{ cwd, root }`，`getWorkspaceRoot`（Python 中为 `get_workspace_root`）读取根。

## Alternatives considered

**迁移时改写 header。** header 是用于存储、分组和权限根的身份元数据；[工作目录记录](2026-09-13-session-working-directory.zh.md)否决了改写它，所有同类产品也都保留不可变的起点。

**为迁移新增事件类型。** 新增普通事件类型同样是同版本变更，但旧读者遇到未知的必需事件会拒绝重建日志，进入过工作树的 Session 在旧读者那里将无法打开。在既有事件上增加可选属性让旧读者保留它们本已理解的当前目录。

**让根跟随每次 `cd`。** `cd` 进入 `packages/foo` 会把文件树重新定根并把写边界缩到该子目录，而用户仍在同一个项目上工作。

**读取时从 Git 推导根。** 目录服务需要在投影内使用 Git 和文件系统 I/O；锚与词法包含关系对日志而言是纯粹且确定的。

**每个工作树一个新 Session，从不迁移。** 面向模型的工作树工具已经让同一个 Session 在新检出目录中继续；forge 的新 Session 工作树路径与该工具最终都落到同一种迁移。

消费方按感知目录的对象划分。模型的文件、搜索与进程工具从当前目录解析相对路径。用户看到的、以及描述项目的一切都读取工作区根：沙箱 `workspace-write` 边界、工作区文件服务与桌面文件拖拽、变更记录器、文件树、交付物、在应用中打开操作与 Session 行、新开的侧栏终端、`@` 文件候选、技能目录、项目指令发现和 LSP 工作区。光标与根不同时，用户上下文在当前目录旁给出根，使模型能够解析用户以根为基准的 `@` 引用。

沙箱策略通过执行环境的文件系统，从根的 `.git` 指针与 `commondir` 推导出链接检出目录的 Git 管理目录，在进程生命周期内按根保留，并加入解析出的额外可写根；工具执行等待该推导完成，会话创建与目录变更提前启动它。Windows ACL 限制为每个额外根添加一条工作区 SID 的常驻 ACE，而不是拒绝该策略。迁移之后，原始项目只能通过 Git 管理目录写入，不再整体可写。

## Consequences

消费方可以向目录服务提出三个问题并得到三个答案：Session 从哪里开始、在哪个检出目录中工作、相对路径从哪里解析。既有日志对任何读者的含义都不变：它们没有锚，因此根就是原始项目。锚按记录原样比较，因此通过符号链接或以不同大小写记录的 header 永远不包含后续变更记录的规范路径；此时根停留在原始项目上。在链接工作树内打开的 Session 可以在 `workspace-write` 下运行 `git commit`，共享的 `.git`（包括其钩子与配置）对该 Session 可写，正如它对主检出目录中的 Session 一样。根内部的 `cd` 不再重新加载项目指令基线或技能目录。工作树快照夹具与目录通知携带根的文本。
