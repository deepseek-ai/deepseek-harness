# Agent Note: Team 任务板复用普通 subagent 等待

Status: implemented

[English](2026-10-19-team-task-board-inbox.md) | 中文

## 问题

subagent 树已经提供身份、发现、路由和生命周期。第二份 Team 名册可能根据过期历史授予分配权限，并重复成员导航。Team 范围状态等待会观察无关活动，却漏掉调用者已有的待处理输入。任务日志已经拥有待查询状态，将任务板唤醒持久化为消息仍会增加未读状态和消息 schema。

## 决策

subagent 树就是 Team。普通控制工具独立于可选任务板，负责通信、发现、中断和 `wait_agent`。Team 工具负责任务策略和必需 Team 身份，不向普通 subagent 组合添加二者。Team 负责任务存储、依赖和比较并交换命令。分配接受根或任意已发现的可继续执行后代。历史名册不授予权限；Team 面板显示任务，普通导航负责成员。

`wait_agent` 先订阅，再检查当前调用者的下一步收件箱。已有待处理输入时立即返回；后续输入结束等待。面向同一 Agent 的 `agent/wait-notified` 事件也结束当前等待。其他收件箱、其他 Agent 的信号、排队的下一轮输入和状态变化不会结束等待。等待既不消费输入，也不启动 Agent。等待结束会移除监听器和定时器，包括超时、取消、释放或插件卸载。

任务追加并刷盘成功后，Team 为同树所有驻留 Agent（包括调用者和根）发出该通用 Agent 作用域信号。信号仅结束当前等待：不保留未读状态，不增加收件箱条目，也不能使后续等待立即返回。信号绝不恢复冷成员或启动空闲轮次。等待结束后，调用者先读取当前任务再行动。

任务状态保留在现有日志中。信号是临时运行时事件，不是 Session 事件或消息；普通工具结果记录等待中的模型所观察到的结果。历史名册、邮箱和任务代次保持可读且不变。这部分取代 [Agent Teams](../feature/2026-08-05-agent-teams.zh.md) 和 [subagent 队友](2026-10-15-agent-teams-as-subagents.zh.md) 中的名册与等待决策。其任务持久性和单一身份理由继续生效；[必需运行时身份](2026-10-13-team-identity-runtime-context.zh.md)负责保留规则。

## 考虑过的替代方案

**保留 Team 成员关系与独立等待工具。** 这会重复树权限和等待生命周期，让过期名册行或无关活动影响当前工作。

**将任务板通知持久化到每个收件箱。** 任务日志已保留每个修订。持久通知仅为打断当前等待，就增加消息类型、未读状态、合并和投递失败恢复。

**轮询 Agent 状态或启动每个空闲任务所有者。** 活动状态不能标识有用输入，任务就绪也不授权新轮次。需要时通过显式消息继续空闲成员的工作。

## 后果

任务完成、收件箱可用性、当前等待和 Agent 生命周期保持独立。等待之外的变更有意不被记住；调用者在决定下一步工作时查询当前任务。任务日志保留已提交修订，不在接收者 Session 中存储重复通知。

验证区分已有收件箱输入和临时信号，隔离调用者与树，排除下一轮输入及状态变化，并覆盖等待清理和刷盘后发信号。分配验证保留任意深度和历史记录无权限场景。
