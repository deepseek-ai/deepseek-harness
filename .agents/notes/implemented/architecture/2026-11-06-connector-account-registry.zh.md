# Agent Note：连接器账号使用一个 Host 注册表和一个浏览器一半

Status: implemented

[English](2026-11-06-connector-account-registry.md) | 中文

## 问题

连接器插件会在插件页显示账号区块。CLI 应用插件的账号保存在厂商 CLI 中；MCP 连接器通过 MCP 管理器保存 OAuth 授权。两类插件需要同样的界面：插件包的区块、标题旁标签和开启引导，在会改变 DSH 之外账号状态的操作前确认，以及只在发起操作的浏览器中显示的提示。客户端插件不能与其他功能插件共享运行时代码（[packages/client/AGENTS.md](../../../../packages/client/AGENTS.md) 第 3 条），因此每类连接器各有一个浏览器一半，就会把同样的代码写两遍，副本还会逐渐不一致。如果由浏览器决定账号状态，或在两个 Remote 之间转发标识，Host 就无法在没有浏览器的情况下完成流程。

## 决定

[`@deepseek-ai/dsh-client-ui-connector-account`](../../../../packages/client/ui-connector-account/README.zh.md) 为所有连接器类型提供一个 Host 注册表 `ctx.connectorAccounts`、一个 `connectorAccounts` Remote 和一个浏览器一半。

| 部分 | 约定 |
|---|---|
| 注册 | `register({ key, packageName?, source, operations, copy, present })` 返回撤下账号的销毁函数 |
| 键 | 在已注册账号中唯一，且与包无关，因此没有插件包承载的账号（如在 Settings 中配置的服务器）也能注册 |
| 包 | 决定由哪个插件包页面承载区块和标签；一个包最多承载一个账号 |
| 来源 | 注册方的账号：`snapshot`、`observe`、`refresh`、`start` 和 `cancel` |
| 展示 | Host 上的 `present(view)` 给出阶段、状态文字、标题旁标签、按钮及其命令、确认、失败信息，以及开启引导启动的操作 |
| Remote | `watch`，以及按键路由到账号来源的 `start(key, operation)` 和 `cancel(key, id)` |

除了打开授权页，其余都由 Host 决定。浏览器不知道账号如何连接：它只收到展示内容、进行中的操作及其授权页，以及带成功文本的最新结果。浏览器一半只保存属于本浏览器的东西：它发起的操作（授权页只在这里打开，成功只在这里报告）、最新提示，以及它的流是否在推送。按钮自己调用 Remote 的 `start` 和 `cancel`，每个界面自己保存未完成状态。

页面只注册一个标题旁标签条目和一个提示条目；对每个带包名的账号，再注册一个区块和一个开启引导，因为这两个插槽以包为键。

## 考虑过的替代方案

**一个浏览器一半背后有两个注册表。** 否决：浏览器要同时跟随两个 Remote，并为每个按钮选择调用哪一个，这又是在 Host 服务之间转发；两个 Host 注册表的代码也会相同。

**每类连接器各有一个浏览器一半。** 否决：客户端插件不能导入彼此的值，共用界面就要写两遍，并逐渐不一致。

**通过 `PLATFORM_MODULES` 或浏览器端服务共享浏览器一半。** 否决：模块表只留给由 shell 预置的基础设施和静态库；浏览器端服务会把注册留在浏览器中，而这些注册只是重复 Host 已知的信息。

**由浏览器根据注册方的原始状态推算账号阶段和操作。** 否决：哪些操作可用的规则会放在 Host 无法测试和执行的地方，浏览器还需要注册方自己的 Remote。

## 后果

注册表和浏览器一半只有一份。新的连接器类型只需在 Host 上编写来源和 `present`，不需要浏览器代码。账号规则与拥有它们的服务在一起，Host 不依赖浏览器就能执行每个操作。

注册方需要把账号状态映射到五个阶段（检查中、连接中、已连接、未连接、不可用）；超出这些阶段的状态通过状态文字和说明表达。无论是否安装了连接器插件，Web 与桌面端组合都会加载注册表。启动调用返回后才打开的授权页可能被浏览器拦截；区块中的打开按钮可以再次打开它。
