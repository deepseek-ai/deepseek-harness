# Agent Note: 环境运行器在每次运行时选择句柄

Status: implemented

[English](2026-11-26-environment-runner-selects-handle.md) | 中文

## 问题

[最初的执行环境记录](2026-11-04-environment.zh.md)将一个环境句柄绑定到每个定义。按调用选择环境的工具（例如 `read(filename, host)` 或由 Session 选择的 host）因此必须为每个句柄保留一个运行器，并在每次调用前查找它。句柄不影响定义发送或缓存的内容：定义哈希只涵盖 `[source, methods]`，注册表也按每次调用解析的句柄来索引注册项和连接。

## 决策

`ctx.environments.define(fn, { result, handlers })` 固定函数源码、其结果校验、发起端处理函数及其名称。返回的 `EnvironmentRunner` 以环境句柄作为第一个参数，其后是参数和 `{ signal, confirm? }`。每次运行在开始时解析持有该句柄的注册项，因此插件加载时创建的一个定义可服务所有环境。

处理函数仍属于定义。如果调用方的处理函数需要某次调用的 host 对象，该调用方仍为每次调用分别定义。本记录部分取代原记录中定义绑定其句柄的决策；原记录的其余部分仍然有效，并与本记录互相链接。

## 考虑过的替代方案

- **将句柄保留在定义中，并由每个工具按句柄缓存运行器。** 否决：每个按调用选择环境的工具都要重复同一缓存，而注册表已按句柄索引连接，并按哈希索引定义缓存。
- **同时接受两种形式。** 否决：两种指定环境的方式会增加公开接口，却没有需要绑定形式的消费方；环境固定的调用方在每次调用时传入同一句柄即可。

## 影响

- 按调用选择环境的工具为每个函数保留一个运行器，而不是为每个句柄保留一个。
- 连接的定义缓存及其哈希不变：在不同环境中运行的相同定义复用同一哈希，每个连接只接收一次该定义。
- 每个调用点都指定其句柄，包括只使用一个环境的工具。
