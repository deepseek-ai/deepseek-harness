# Agent Note: 源码构建的 CUA helper 使用开发签名身份

Status: implemented

[English](2026-10-29-cua-dev-signing-identity.md) | 中文

## 问题

源码检出用临时签名编译 `DSH Computer Use.app`。macOS 按 Bundle ID 和被授权代码的指定要求保存辅助功能与屏幕录制授权，临时签名的指定要求就是代码哈希。因此每次构建内容变化、每换一个 worktree，都需要重新授权；这些构建还与正式 helper 共用 Bundle ID，会替换正式版的授权条目。

## 决策

Host 以开发版构建源码检出，Bundle ID 为 `com.deepseek.harness.computer-use.dev`，名称为 `DSH Computer Use Dev`，应用包文件名为 `DSH Computer Use Dev.app`。macOS 隐私列表和 helper 返回的启动应用名称使用应用包文件名，因此文件名也需包含 Dev。正式版及其打包流程不变。按[共享 helper 决策](2026-10-09-cua-shared-native-helper.zh.md)的要求，授权仍归经 LaunchServices 启动的 helper 应用。

`sourceSigning` 由 macOS provider 定义，支持 `ad-hoc`、默认的 `local-identity`，以及指定已有证书的 `{ identity, keychain? }`。自动身份及密码存放在 `$DSH_HOME/computer-use-dev-signing`，未配置 home 时使用 `~/.dsh`；首次构建创建证书，此后同一 home 的构建都复用它。Host 使用公共 home 路径解析器并把结果传给 Python。临时签名和用户证书模式不读取或创建自动身份。用户证书的解锁和维护由用户负责。

初始化在专用钥匙串中创建自签名证书，将随机密码存入权限为 `0600` 的文件，通过密钥分区列表允许 `codesign` 访问，并把钥匙串加入用户搜索列表。自动构建每次签名前用保存的密码解锁，避免密码或密钥访问窗口。同一 home 的初始化和移除使用文件锁串行执行。已有身份记录但钥匙串缺失时保留记录并报错，只有用户显式移除后才允许重新生成。签名要求包含 Bundle ID 和证书，使用同一证书的构建不依赖代码哈希或路径。

即使不使用时间戳服务器，证书签名也会写入签名时间。开发版发布时记录每个未签名应用与签名身份对应的目录，再次构建时直接选中该目录，不重新签名，因此相同源码保持同一个可执行文件摘要和同一个共享服务。缓存使用证书指纹；显式证书名称可能对应续期后的证书，因此不复用缓存。签名初始化失败会中止构建；异常信息不包含密码或完整命令参数。`--identity` 选择用户证书签名，与 `--signing` 互斥。

## 考虑过的替代方案

**把权限交给启动终端。** 直接启动服务时，macOS 把权限归属到启动 DSH 的终端或编辑器。该应用运行的所有程序，包括模型执行的命令，都会带上这些权限。

**默认临时签名。** 可以避免保存私钥，但二进制变化后可能需要重新授权。默认自动生成固定身份，让普通源码构建无需手动准备证书；临时签名仍可显式选择。

**把自签名身份放进登录钥匙串。** 登录钥匙串已解锁且在搜索列表中，但要让 `codesign` 不弹窗地使用其中的新私钥，需要用户的登录密码。

**只在签名期间把钥匙串加入搜索列表。** 正式打包脚本对单次调用这样处理。多个 worktree 并发构建时会互相覆盖读取和恢复的列表，构建被中断时条目也会残留。

**用固定的启动器运行各 worktree 的 helper。** 授权会跟随启动器，但任何本机进程都能让它带着这些授权运行任意可执行文件，暴露面与保存的私钥相同，还少了签名检查。

## 后果

使用同一 DSH home 的自动签名构建共用签名要求，实际授权在重建和跨 worktree 后是否保留仍需手动验证。同一用户的进程能读取密码并使用开发身份签名，正式 helper 使用不同的 Bundle ID。删除 DSH home 会删除自动身份，下次构建生成新证书并需要重新授权；这也让 home 重置能清除签名状态。系统设置中的授权和钥匙串搜索条目不随目录删除而消失；后续初始化会清理同路径的失效搜索条目。主动移除身份前需选择临时签名或用户证书，以免下次构建重新生成。真实签名 e2e 核对不同输出目录的构建共用要求、用户指定证书可用，以及移除后搜索列表恢复。
