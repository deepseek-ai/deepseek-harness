# Agent Note: 通信范围由子代理树决定

Status: implemented

[English](2026-10-16-tree-wide-agent-communication.md) | 中文

## Problem

一个 Team 在根的整棵子代理树中共享任务板。把发现和消息限定在相邻成员之间，会迫使深层成员在共享任务的同时，仍通过父级转发工作。

## Decision

`list_agents` 从调用方的在线根开始，列出该根与所有可达的可继续后代，包括调用方。父级 id 和深度始终相对根计算。现有父级目录仍是权威来源；不单独存储 Team 目录。

`send_message` 接受同一棵树中的其他根或可继续成员。发送者必须是确切在线根或驻留的可继续子代理。跨分支路由保留实际发送者，验证持久子级描述符和父级目录，并按记录的父级恢复冷祖先。祖先恢复不会向这些祖先投递发给目标的消息。最终收件箱准入重新检查发送者与目标父级。接受前的取消或拒绝会释放新建的恢复工作；已接受输入遵循普通 Agent 持久化。

父级所有权仍管理容量、恢复和释放。`interrupt_agent` 保留仅祖先可执行的权限。普通 Session 分叉领导独立树；外部执行和一次性执行不能接收后续消息。

本决策仅替代[相邻消息](2026-08-27-adjacent-agent-steer-messaging.zh.md)与[子代理队友](2026-10-15-agent-teams-as-subagents.zh.md)中的邻接和发现范围限制。它们的共享收件箱、调度、发送者归属、生命周期和 Team 复用决策仍有效。成员使用 Session id 寻址。

## Alternatives considered

**通过父级转发。** 这保留了更窄的路由实现，却让创建层级决定谁能协作。共享工作需要跨分支直接通信。

**单独的 Team 目录与投递。** 第二份成员列表和消息路径会重复现有目录、收件箱与恢复生命周期。树成员身份已经提供所需通信范围，无需另一个注册表。

## Consequences

发现输出随整棵树增长。冷投递在恢复祖先时可能占用多个激活槽位，容量或历史不可用时会被拒绝。发送者的在线祖先链必须保持完整。列表是快照，不保证之后发送成功。并发操作保留普通收件箱接受与释放顺序。
