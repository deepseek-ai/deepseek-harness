# Agent Note: 基于 section 的系统更新

Status: implemented

[English](2026-10-21-section-based-system-updates.md) | 中文

## 问题

整份提示词更新会在任一贡献方变化时重复未变的指令。独立的贡献方状态、退役队列和临时准入记录重复了生命周期与提交事实，而进程内比较会丢失恢复和 fork 历史。作用域覆盖需要改变有效指令，却不能让仍有活跃所有者的逻辑来源退役。

## 决策

`section()` 是唯一的来源注册 API。名称标识逻辑指令；普通 `system/message` 事件记录其规范文本、顺序和状态。每个 Session 对这些事件的投影是已提交状态的权威来源。运行时定义保持共享，因为部署和预设插件可以在 Session 创建前注册。Session 提供自身的已提交状态和回调上下文。

### 注册与退役

每个 Cordis effect 拥有一项注册。组装先选择最近的可见作用域，再选择其中最新的活跃注册。选中定义提供文本、顺序、替换措辞和完整模式；只对它的文本提供方求值。移除被遮蔽的所有者不会移除覆盖者。移除覆盖者会将继承定义作为普通更新呈现。Persona 前缀和后缀采用同样的注册：前缀文本与完整模式共同继承，后缀独立继承，subagent 也遵循此规则。

退役同时要求可见链中不存在活跃注册，且该 Session 已提交该名称的文本。每个 Session 保留其观察过的定义；最后被释放的已观察注册提供字面量退役措辞，否则由服务提供点名来源的通知。显式 dispose（资源释放）和插件清理都不会对已释放的提供方求值。一个 Session 完成退役不会清除另一个 Session 的通知。已提交退役会从投影删除来源，因此后来重新引入按普通首次引入处理。

释放记录生命周期状态，而不注册另一项贡献。若有效文本和顺序未变，组装前的关开循环不发送任何消息。来源从未提交就无需退役；该 Session 不再有已提交文本后即可释放非活跃引用。需要独立退役的指令使用不同名称。

### 规范记录与固定组装

组装在异步展示中间件前捕获来源值和生命周期状态。最终规范化的展示结果固定各段；循环在提交时取得其更新，此时将它们与已提交投影比较。文本在直接比较前完成插值并去除首尾空白；数字顺序和名称决定排序，仅顺序变化也会记录。规范文本和每条通知各占一个去除首尾空白的文本块。分隔符由适配器负责，因此序列化添加的空白不属于来源贡献。

`source.sections` 为规范块和通知记录归属，无需解析其文案。活跃记录具有 `contentIndex`，包括空字符串；退役记录省略它。可选的 `noticeIndex` 列出替换或退役块，不区分通知种类。索引指向所在消息，不能重叠或重复。整份提示词的替代通知涉及多个来源，因此不归属于单一来源。通知对模型可见并写入日志，但不参与规范文本比较。[Session 格式规则](../../../../docs/session-format-status.zh.md)负责持久化校验。

初始为空的普通段不贡献带归属的文本。将已准入来源变为空文本是撤回指导的文本变化，而非释放。首次接受的组装即使为空也保留系统头节点；空内容保持可寻址并写入日志，但不产生模型请求消息。进入或改变完整提示词时追加显式替代与重置语义；退出时重新引入当前普通段。由早期版本、格式迁移或导入器写入的、不含 `source.sections` 的系统消息不会获得虚构的来源元数据；它将[重建](2026-11-09-deferred-system-compaction.zh.md)标记为待处理。除此之外，更早的消息保持原位。

被拒绝或取消的准备不提交任何内容。后续组装重新将当前值与已提交事件比较。消息一旦追加，取消不会撤销它们。捕获后的来源变化等待下一次组装：来源可以在其引入被捕获后释放，该引入仍会提交，再由下一次组装退役。这接受偶尔冗余的引入与退役，以免丢失撤回或增加第二个观察点。重试复用已接受的组装，不再次提交增量。[压缩](2026-11-09-deferred-system-compaction.zh.md)之后，同一批已捕获段在下一次模型尝试时生成完整重建。

普通路由、工具、请求序列和重启变化不合并指令。这保留了[不变前缀保证](../bug-fix/2026-10-22-series-start-unchanged-prompt-prefix.zh.md)及指导的生效时机。所有保留的系统消息都计入系统 token；适配器通过原生系统消息、提醒或合并系统字段保留新增内容。[表面节点表示](2026-09-02-system-prompt-as-surface-node.zh.md)仍是持久表示。

计划模式保留有条件适用的策略，并在退出和重新进入时修改独立状态段，避免重复策略文本。用户切换通知跟随已提交的用户选择变化，而不依赖请求头：请求头描述请求配置，不必随系统段变化。取消的选择不发通知；获准的工具退出使用其工具结果。初次进入和已提交的空闲切换都会被说明，无需第二份最后已说明模式状态。

## 考虑过的替代方案

**并行来源 API 与可变准入字段。** 考察过的 #4969 设计支持任意状态和显式退出，但文本比较已覆盖本功能。Last-admitted 和 last-committed 字段重复了候选及事件派生投影，并为拒绝、取消和重放增加同步。进程内最后文本缓存还会遗忘恢复和 fork 状态。

**显式退役调用、轮询或待发通知队列。** 最初偏好生产方清理，以避免服务自行检测存活状态。Cordis 已调用精确的注册清理，因此注册时的字面量措辞提供同一信号，无需清理时访问服务。组装时选择退役可合并重新注册，无需第二套队列或取消机制。

**拒绝重复名称或使每个被释放所有者退役。** 单一所有者避免回退规则，却阻止作用域覆盖。逐个所有者退役会撤回仍由继承定义提供的指令。显式作用域优先级和逻辑来源退役解决这两种情况；重复名称不再检测意外重复加载。

**全局最后注册优先或每个 Session 一个服务。** 全局加载顺序会让后来的部署重载覆盖更具体的 agent（智能体）指令。Session 独立服务仍需转发更早的共享注册及后续释放，或为每个 Session 复制插件和资源。共享作用域层配合每个 Session 的已提交状态避免了这两种问题。

**独立 persona 注册表。** 普通段已能独立解析前缀与后缀、携带完整模式，并在释放时恢复继承定义。另一份注册表和组装覆盖层会重复这些规则。

**延迟来源求值、重试求值或逐来源摘要。** 延迟对来源求值会改变固定观察点及已接受候选。哈希增加持续开销和另一种表示，却无法省去规范文本存储。直接比较使用恢复所需的现有文本。

**退出时移除计划策略或每次重启都重建。** 持久的条件策略避免重新进入时再次发送。重启重建会将当前指令移到中间轮次之前，丢弃原有生效时机。压缩通过独立决策明确允许这种移动。

**持久化未提交的退役定义。** 恢复需要稳定的作用域标识、重新注册时的持久取消，以及清理后的关闭写入。仅运行时设计接受恢复缺口，不引入这些机制。

## 影响

投影随有效来源数而非对话长度增长，避免逐请求扫描历史；检查点只是可丢弃的重放优化。未变化的段不会重复，但保留的指令和通知仍消耗上下文。前缀复用依赖适配器表示，并无保证。任意非文本过渡状态不在本功能范围内。

运行时定义和未提交释放状态不跨重启保留。恢复或继承种子的 Session 无法恢复本地从未观察且不再注册的来源专属退役措辞。这也影响一种 fork：它的种子截止于已完成轮次，而父 Session 在排除的开放轮次中已将来源退役并释放；复制父 Session 的当前映射无法恢复那个历史定义。普通准入不会自动使缺失来源退役，也不保留历史定义。启动和继承来源恢复仍未实现；压缩则采用当前活跃来源。

聚焦的注册、组装和循环测试覆盖精确所有者清理、回退、每个 Session 的退役、丢弃候选、捕获后释放、重新引入、persona 继承与重试复用。持久化和请求重建验证规范元数据及模型可见块在重放中保持一致。压缩记录负责重建覆盖。
