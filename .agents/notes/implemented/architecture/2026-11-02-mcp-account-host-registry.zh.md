# Agent Note: MCP 连接器账号的 Host 注册表

Status: implemented

[English](2026-11-02-mcp-account-host-registry.md) | 中文

## 问题

Linear、Notion、腾讯文档等连接器插件在 Host 上向 MCP 管理器注册 OAuth MCP 服务器，并在插件页面显示其账号：带状态和操作的区块、标题标签、开启后的引导、退出登录确认和提示。管理器已经持有授权尝试、grant 和服务器状态，而每个连接器都需要同样的界面。在浏览器中注册账号，会让每个连接器都提供一个浏览器一侧：其中一份 41 个 key 的字典有 26 条文案在各连接器间完全相同，另有一次注册重复其 Host 一侧已注册的服务器名。

## 决定

[`@deepseek-ai/dsh-client-ui-mcp-account`](../../../../packages/client/ui-mcp-account/README.zh.md) 中的 Host 服务 `ctx.mcpAccounts` 保存账号。连接器的 Host 行注册其服务器名、bundle 包名，以及以 `LocalizedText` 表示的、指明其服务的文案。注册放在 `ctx.inject(['mcpAccounts'], …)` 中，因此没有注册表的 profile（如 headless）加载连接器时不带页面。Web 应用组合加载注册表。

注册表通过一个 `mcpAccounts` Remote 提供所有账号，并附上管理器对其服务器的视图；授权、取消、退出登录和重启仍走管理器的 Remote，它本来就接受服务器名。一个浏览器一侧渲染所有账号的界面，并保存属于单个浏览器的状态：只在发起尝试的浏览器中打开授权页面，只在那里报告提示，并在自身操作未完成时忽略点击。26 条共用文案放在套件字典中。

## 考虑过的替代方案

**浏览器注册。** 每个连接器的浏览器一侧以自己的字典命名空间向浏览器中的 `ctx.mcpAccounts` 注册，并自行跟随管理器流。这需要每个连接器一个浏览器包，而它只是重复其 Host 一侧已注册的内容，并且每个浏览器中每个账号各开一条管理器流。

**用共享模板生成连接器文案。** 用一份以服务名为占位符的字典可以去掉 15 条连接器专属文案，但这些文案不只服务名不同，例如退出登录会删除什么；而且中文里拉丁文名称两侧的空格取决于其位置。因此由各连接器以 `LocalizedText` 提供这些文案。

**通过注册表执行操作。** 注册表可以按包路由 `startAuthorization` 等操作。管理器的 Remote 本来就接受服务器名，路由只会多出第二个操作入口，而不增加任何检查。

**与 CLI 账号共用基座。** CLI 账号注册表同样为插件页面注册 Host 账号，但 MCP 账号遵循管理器固定的授权状态，而 CLI 账号呈现各厂商自己的状态。共用基座会把两个注册表耦合起来，却不能从任一方删去代码。

## 影响

连接器不为账号提供任何浏览器代码；其 Host 行注册账号，由套件渲染。每个浏览器为所有账号打开一条流，它在 Host 上跟随一条管理器流。Host 行加载失败的连接器不显示账号区块，而插件页面仍列出该 bundle 及其加载失败。

Host 测试固定注册、同一包或服务器的第二个账号被拒绝、与管理器流的合并及其失败和结束，以及卸载。客户端测试固定只在发起尝试的浏览器中打开授权页面、提示、未完成操作保护，以及每个账号的插槽注册及其移除。
