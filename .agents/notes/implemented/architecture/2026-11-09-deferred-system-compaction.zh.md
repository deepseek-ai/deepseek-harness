# Agent Note: 压缩后延迟重建系统指令

Status: implemented

[English](2026-11-09-deferred-system-compaction.md) | 中文

## 问题

压缩必须选择恢复对话时使用选定历史终点的指令，还是当前注册的来源。历史重建需要分别解释规范记录，以得到终点呈现和最新已提交状态，也无法包含未提交的来源变化。

手动压缩可以在 Session 空闲时完成，但已发布的读取器要求普通 `system/message` 事件位于开放的模型步骤内。因此，立即改写系统指令需要特殊的关系验证，或另一种持久事件及读取实现。压缩移除更新所比较的指令后，压缩前计算的更新也不再正确。

## 决策

压缩对既有对话生成摘要，将当前来源求值留给下一次模型尝试。该尝试所在步骤的组装按普通作用域解析、插值和首尾空白移除规则捕获活跃来源，包含未提交变化；重建省略已退役来源和过渡通知。[按段更新](2026-10-21-section-based-system-updates.zh.md)负责注册、生命周期和增量准入。本决策取代历史端点快照及中间的立即重建设计。

既有的已提交 `compaction/summary` 事件在准入投影中将系统重建标记为待处理。不含 `source.sections` 的系统消息同样会标记：早期版本的整段提示词和导入器写入的空头节点由同一重建替换，不再另行追加替换消息及其通知。组装固定段文本和生命周期，但不计算更新。每次模型尝试前，循环向组装结果请求其更新；该调用将已捕获的段与当时的投影比较，并在重建待处理时返回完整重建。因此，组装与提交之间的压缩，或同一步骤多次尝试之间溢出恢复期间的压缩，都不需要再次组装。重试只会得到待处理的重建，因此其他写入方在两次尝试之间记录的系统变化等待下一次组装，捕获后的来源变化也是如此。

在开放步骤内，普通 `system/message` 替换先清空保留的系统增量，再以完整的当前提示词重置初始系统节点。压缩范围外的增量也会被清空。最终带归属的重置确立已提交来源状态，并完成待处理重建。空指令保留可为空的系统头节点，但不向模型请求添加消息。被拒绝或取消的准备不提交候选；替换序列中断时，重建仍保持待处理，直到头节点重置提交。待处理状态可以跨重启从日志恢复，无需保留运行时定义。

摘要器保留原始已记录指令、所选对话及可缓存顺序。框定摘要的大小检查独立于延后的系统文本，使用既有的仅比较摘要方式。复用这套逻辑避免将压缩重新耦合到当前来源组装。普通系统替换也保留既有的标量上下文压力计数；本决策不保证没有遮蔽价格元数据的替换之后压力精确。

## 考虑过的替代方案

**从已记录段重建历史指令。** 先前设计将规范记录折叠到选定端点，省略退役来源和通知，并让此前的完整快照重置该历史折叠。摘要准备可在收集选定消息时一并收集记录，无需第二次完整日志读取。独立快照用途避免较旧快照在保留后缀更新之后写入时，使最新准入投影回退。这在重复压缩中保留了精确的端点文本和顺序，却需要对日志作两种解释，并排除未提交变化。当前指令负责恢复后的对话，因此明确移除这种历史展示及其测试；运行时回调无法重现它。

**将历史快照限制为前缀，或插入到任意范围之前。** 仅前缀压缩可使用既有操作，将始终存在的头节点（包括空头）替换为端点状态；它放弃中间范围，以免历史指令移到保留的更早对话之前。支持任意历史范围则需要插入和替代语义。当前来源重建放弃端点保真，因此压缩器保留既有范围选择与头节点保护，无需快照专用限制或插入操作。

**立即用普通消息替换系统指令。** 这复用消息词汇，但空闲压缩需要已发布开放步骤规则的例外。延迟重建提供普通开放步骤，无需另一条 Session 格式规则。

**必需的原子重建事件。** 中间的 `system/rebuild` 设计通过纯投影同时替换头节点、清除后续系统消息并重置已提交来源状态，保留对话位置。在破坏性的摘要替换前重建可在准备失败时保护指令，但需要协调事件顺序，并单独计量被替代的系统 token；整个压缩仍包含多个事件。读取器需要该投影，旧读取器会安全拒绝未知必需事件。立即的空闲检查与重启可见性推动了该设计，但不足以证明另一种事件、读取器依赖和计量路径的必要性。不再保留兼容读取器。重新引入需要具体的即时空闲可见性或原子系统替换需求。

**在组装时计算更新，压缩后重新捕获。** 将计算出的增量保存在组装结果上，需要同时记录最近一次压缩，并在之后的压缩使其失效时再次组装。循环因此需要按固定顺序调用系统服务上的新鲜度检查、待重建查询和提交操作，来源回调也会在同一步骤内运行两次。在提交时比较只需要一次调用，并复用该步骤已捕获的段。它放弃了同一步骤内组装与压缩之间发生的来源变化；这些变化在下一步骤作为普通更新到达。

**共同检查摘要和重建系统的大小。** 这可以拒绝被新系统文本增长抵消节省量的摘要，但要求在压缩期间求值这些文本，并维护联合计价。保留的仅摘要检查不保证无关来源增长后下一次完整请求仍然更小。

## 影响

已完成的空闲压缩可以继续显示旧的保留指令，直到模型尝试开始。此显示延迟是可接受的。系统替换按顺序可见，并非原子可见，但模型只在准入完成后才被调用；失败的尾部清理或头节点重置仍可通过待处理标记恢复。原始事件仍保留在持久日志中。

当前指令移到保留对话之前，后续系统更新在归并后从模型历史中消失。重启后缺失的注册不会进入完整提示词，即使普通增量组装会保留其已提交文本。同一步骤内组装与压缩之间发生的来源变化同样不会进入，直到下一步骤将其准入。由早期版本写入的 Session 在其首次模型尝试时重建一次，该次请求因此无法复用已缓存的请求前缀。这放弃了精确的历史指令位置和立即空闲可见性，同时保留既有 Session 词汇、表层操作和已发布读取器规则。

验证覆盖空提示词、当前及未提交来源、保留对话、中断清理、重启恢复、重复压缩，以及组装与提交之间的压缩。压缩测试保留仅摘要缩减检查和恢复行为。重试测试确保无论是否发生压缩，捕获后的来源变化都不会在该步骤内准入。
