# Agent Note: Windows 逐目录写入身份

Status: implemented

[English](2026-10-28-windows-directory-write-identities.md) | 中文

## 问题

[会话级可写根目录](2026-10-26-session-writable-directory-effects.zh.md)允许独立插件向执行策略添加目录。如果 SID 由完整目录集合派生，每次组合变化都需要向未变化的目录添加常驻 ACE，并重新传播整棵目录树。

## 决策

每个规范可写目录拥有一个确定性 SID，仅在该目录上授予它。每次新执行携带全部允许目录的 SID。提供方按目录缓存授权，并在执行前重新检查 ACE，避免目录重建使缓存失效。共享目录在不同 Session 和权限组合之间复用同一个常驻授权；未携带该目录 SID 的 Session 无法从该授权获得权限。

`AclSandbox` 从规范化、去重后的路径派生身份，不接受调用方为任意目录列表选择一个 SID。每个解析后的 SID 都有明确的分配所有者，包括部分初始化失败时。私有临时能力仍按活跃 Session/工作区对独立；令牌默认 DACL 继续优先使用私有临时 SID。后续执行改变允许根目录时，已运行进程保留启动令牌。

目录授权使用 Node 按主机平台实现的 `path.relative` 比较传入路径与物理路径，SID 派生则保留物理路径的拼写。这接受普通 Windows 大小写差异，无需加入逐级遍历路径的实现。比较假定 Windows 路径不区分大小写；旧式 8.3 别名仍不受支持。这里有意优先支持常见路径语法，而不穷尽文件系统身份处理。

## 考虑过的替代方案

**每个完整目录集合一个 SID。** 排序、去重后的 JSON 编码可生成无歧义身份，并隔离不同权限的执行。但每种新组合都会向未变化的目录添加另一个 ACE，并重复目录树传播。逐目录身份通过独立复用提供相同的后续执行语义。

**将工作区 SID 扩展到额外目录。** 这会为已经持有工作区 SID 的进程及使用该工作区的其他 Session 累积权限。添加目录必须选择另一个已有目录能力，而不能扩大共享能力的含义。

## 影响

已有的仅工作区 SID 值保持稳定。常驻目录 ACL 编辑比执行存活更久，新执行的权限由令牌携带的 SID 控制。原生 Windows 回归覆盖多个目录能力、未包含目录的拒绝、独立临时授权，以及每个目录仅显式授予自身 SID；可移植测试覆盖令牌内容、分配清理、缓存复用与授权失败重试。[Windows ACL 决策](../feature/2026-08-08-windows-acl-restricted-token-sandbox.zh.md)保留受限令牌机制与硬链接限制；本决策替换其单工作区身份模型。
