# Agent Note: CUA 作用域表面与分离的输入能力

Status: implemented

[English](2026-11-05-cua-scoped-surfaces-and-input.md) | 中文

## 问题

应用对象和窗口对象共享辅助功能操作，但只有显式窗口能截图或发送指针输入。若在两个工厂上分别复制共享方法，就会出现两套需要同步的实现。把只适用于应用的能力检查放进共享基类，会让窗口行为依赖应用级判断。键盘输入也有同样的问题：组合键字符串把按键与修饰键混在一起，完整击键方法无法表达跨调用保持修饰键或单独抬起按键。

## 决策

`CuaSurface` 声明应用对象与窗口对象共享的操作；`CuaApp` 与 `CuaWindow` 通过扩展它增加各自的操作。一个基类工厂负责构建表面，派生工厂注入作用域参数以及 `requireAccessibility`、`requireKeyboard` 检查。共享基类从不为只属于应用的能力分支。

Provider 的启动能力是静态的。平台、支持的方法、应用级辅助功能、键盘作用域、浏览器支持和坐标空间在安装 provider 时固定。原生 `getCapabilities` RPC 只报告运行时权限和会话锁定状态；`installCua` 为模型可见结果合并两层。中立的 RPC 是通用操作表示，不是能力清单；provider 指导文本说明其平台支持的动作。

键盘输入把按键与修饰键分开：`pressKey(key, modifiers?)` 在按住所列修饰键时按下并释放一个键，其键盘修饰键列表是 provider 定义的普通字符串数组。`sendKeyEvent(key, direction)` 只发送一次按下或抬起，不隐式发送相反事件。因此调用方可以保持修饰键或拆分手势；两个方法都不接受组合键字符串，共享 schema 也不枚举平台按键名。

在单个 API 实例内，对象门面按应用句柄保存一份当前辅助功能快照，该句柄的所有应用对象和窗口对象共享这份快照，包括对同一应用的重复选择。`getWindow` 静默执行首次树读取；当 provider 报告应用级辅助功能时，`getApp` 也静默读取。之后的 `getAccessibilityTree` 读取会在分派前使上一份快照失效。门面会为元素操作自动附加最新快照 ID；调用方应使用最新树中的元素 ID，不应假定旧 ID 仍指向同一控件。元素 ID 是 provider 定义的不透明字符串。只有显式 `CuaWindow` 可以截图或发送指针输入。原生 helper 在该门面之后保留自己的应用快照和可选窗口快照；原生层与门面快照相互独立。外部运行时继续负责变量持久化和最终表达式序列化；门面不加入 evaluator。[原生对象决定](2026-09-17-experimental-cua-object-api.zh.md)负责 evaluator 独立性，[共享 helper 决定](2026-10-09-cua-shared-native-helper.zh.md)负责连接生命期。

## 考虑过的替代方案

**在应用和窗口上重复方法**会让每个工厂各自实现同一套辅助功能操作。每次共享改动都需要成对修改，两个表面还可能接受不同的参数或结果。单一 `CuaSurface` 实现让这份行为只有一处。

**在共享基类中加入应用专属分支**会让窗口对象继承只适用于应用的决定和能力检查。由各作用域工厂注入自己的要求，可以让共享操作不依赖使用它的作用域。

**打包的组合键字符串**需要一起解析按键名、分隔符和加号转义，并把平台别名归一化推入共享层。击键与方向是两种语义：`pressKey` 描述一次完整击键，`sendKeyEvent` 描述一个显式方向。分开的按键和修饰键值让这些语义无需解析器。

**在共享 schema 中枚举平台键盘按键**会把可移植的操作 schema 绑定到某个 provider 的按键名，并让每个平台都修改 schema。由 provider 定义字符串，平台可以解释自己的名称，共享 schema 保持中立。

**由原生报告静态能力**会在原生 helper 中重复 provider 配置，并让 helper 负责它在启动前就固定的知识。helper 报告运行时状态；启动能力由 provider 负责。

## 影响

元素 ID 属于应用当前的辅助功能快照。读取一个窗口会替换门面对该应用的当前快照，因此调用方需要重新观察并确认要使用的 ID。新的读取不保证拒绝旧字符串，也不保证 ID 会改变；调用方不得假定旧 ID 仍指向同一控件。指针输入和截图都要求显式的窗口对象；调用方先枚举窗口。

键盘行为遵循 provider 支持的作用域。使用 `sendKeyEvent` 的调用方负责按下与抬起的配对，在 macOS 上，程序结束或用户暂停时会释放本次执行仍按着的键。键盘修饰键名称由 provider 定义，同一字符串在不同 provider 上可能支持不同。

Provider 指导文本负责支持动作的清单。把方法加入共享 schema 并不表示每个 provider 都已实现它；合并后的 `getCapabilities` 结果仍是权限和会话锁定状态的运行时来源。
