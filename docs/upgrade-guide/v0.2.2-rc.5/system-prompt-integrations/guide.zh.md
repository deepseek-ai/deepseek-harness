# 系统章节与自定义集成

[English](guide.md) | 中文

## 变更

后续 `system/message` 事件包含章节更新，而非完整提示词。消费方必须保留所有仍存活的系统消息。接受的组装会将来源文本和顺序与日志状态比较；仅当来源已提交且没有剩余活跃注册时，清理才会产生退役通知。被拒绝的组装不提交任何内容。不含 `source.sections` 的旧式消息仍可读取；下一次模型尝试会以当前章节替换初始系统节点，并清空后续系统消息，与压缩之后相同。

`section()` 接受重复名称：最近的可见作用域优先，其次是该作用域内最后一个活跃注册。清理覆盖后会恢复下一个定义。Plan mode 保留条件指令，并追加 active/inactive 状态更新。

章节在插值后去除首尾空白，保存为独立文本块；系统服务不插入空白分隔符。每个 active 记录都有指向其实际文本的 `contentIndex`，包括空文本更新；retired 记录不提供该字段。可选的 `noticeIndex` 数组标识属于该来源的替换和退役文本块。整段提示词的替代通知保持无归属。通知也会去除首尾空白；退役通知必须非空。

压缩根据已记录的指令为选中对话生成摘要。下一次模型尝试之前，普通系统消息替换操作先清空后续系统更新，包括选区外的更新，再将当前来源写入初始系统节点。空闲期间的检查视图保留旧指令，直到该次尝试。不需要额外的消息投影或 Session 事件类型。

## 迁移

1. 保持章节名称稳定，为独立指令使用不同名称。仅在覆盖场景中复用名称。指令适用期间保持注册活跃；清理注册以撤回来源。可选地提供字面量 `retirement` 文本和 `replacement` 通知；空 replacement 会省略该通知。在两次准入之间清理并重新注册且不改变生效文本时，不会产生多余更新。
2. 更新自定义 transcript、SDK、适配器和查看器消费方，以累计章节，并使用上述索引区分实际文本和通知。保留章节内部有意义的空白；不要用纯空白章节充当分隔符。适配器在格式化请求时选择分隔符。已有日志文本不变；此前未裁剪的文本可能收到一次规范化更新。
3. 自定义组合必须在使用 `system-prompt` 前加载 `session-projection`。自定义循环不再消费 `systemMessages`，而是在每次模型尝试前（包括溢出重试）调用 `PromptAssembly.systemUpdates(retry)`，并按顺序、不让出执行地将返回的每个 `{ message, intent }` 追加为 `system/message` 事件。首次尝试传入 `false`，之后的尝试传入 `true`；之后的尝试只会得到压缩所要求的重建。重试复用已有组装。详见[循环准入](../../../../packages/core/agent-loop/README.zh.md#understand-the-implementation)。
4. 验证未变化的章节不发送消息，变化的章节发送更新，且最后一个可见注册被清理后发送一次退役通知。移除 persona 覆盖后，确认父级 persona 生效。
