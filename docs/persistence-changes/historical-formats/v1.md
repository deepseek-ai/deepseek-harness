# Session V1 persistence format

English | [中文](v1.zh.md)

## Summary

Inspect the V1 persistence types immediately before the V2 writer change. V1 uses the V0 physical row layout, keeps top-level Assistant chunks, and declares its logical header version as the literal 1. This intermediate format has no tag in the captured alpha/RC release archive.

<a id="characteristics"></a>
## Format characteristics

These facts describe the selected checkpoint. The generated tables below preserve the exact field types and optionality.

- `SessionHeader.version` resolves to the literal 1; physical `JsonlHeaderLine.version` remains `number`.
- The logical header requires `isSeeded`, while the physical header still uses optional `seedLength`. This distinction must survive reconstruction of historical headers.
- `assistant/chunk` remains a top-level event. `assistant/message` has no embedded `stream`, and the V2 `assistant/attempt` event is absent.

The [V0/V1 codec](../../../packages/session/session-format-v0-to-v1/src/codec.ts) owns the shared physical layout, including packed chunks and numeric inherited cuts. The [V1-to-V2 migration reference](../../../packages/session/session-format-v1-to-v2/README.md) owns chunk consumption, embedded streams, and sequence remapping; those transformations are not inferred from the type digests.

Packed physical rows use `text-chunks`, `reasoning-chunks`, or `tool-call-chunks`, with `seq0`, `time0`, and `data.turn` / `step` / `index` / `dt`. Text and reasoning rows carry `texts`; tool-call rows carry `id`, optional `name`, and `args`. For N members, `dt` has N−1 time gaps, which may be negative. Member k has sequence `seq0 + k` and time `time0` plus the first k gaps. Physical `sourceEventSeqs` may use encoded ranges; the logical schemas below show expanded number arrays.

## Verification and limitations

The [source-only extractor](../../../scripts/persistence-schema.ts) ran with TypeScript 6.0.3. Reconstruction omits redundant `object` intersection members and discards normalization-unreachable type definitions; it preserves existing `any` / `unknown` and does not substitute opaque types for unresolved imports.

Historical surface-event declarations permit optional `surfaceOp`. This is retained evidence of declared types, not permission to omit fields required by a codec or migration validator. Opaque values, external plugin events, packed body encoding, and runtime relationships are outside the type inventory’s coverage.

```sh
pnpm run verify-persistence-formats
```

The check validates every format through the current writer, schema completeness, bilingual declarations, and generated tables using only this checkout. It does not replay historical applications or establish migration safety. See the [format index](README.md) for maintenance rules and the [current catalog](../../persistence-catalog.md) for today’s declarations.
