# Session V2 持久化格式

[English](v2.md) | 中文

## 概述

查阅 `dsh-v0.1.3-alpha.2` 对应的 V2 持久化类型。Assistant 流内嵌在 message 或 attempt 事件中，物理 header 要求 `isSeeded`，不再存储 `seedLength`。本快照保留 V3 系统消息与信封变更之前的 V2 声明。

<a id="evidence"></a>
## 来源证据

来源为已发布 tag `dsh-v0.1.3-alpha.2`，其写入器常量为 2。[tag 记录](../releases/dsh-v0.1.3-alpha.2.zh.md)说明相邻发布之间的变化。本完整目录同时包含未变化的根类型和该 tag 变化的根类型。

提取的声明来自 `packages/core/session/src/types.ts`、`packages/session/session-persistence-jsonl/src/format.ts`，以及所有第一方 `SessionEventMap` 声明合并及其可达类型。下方源码位置指向该历史源码树，而非当前文件。

<a id="characteristics"></a>
## 格式特征

以下事实描述所选检查点。下方生成的表格保留精确的字段类型与可选性。

- `SessionHeader.version` 解析为字面量 2。逻辑与物理 header 均要求 `isSeeded`；物理 header 没有 `seedLength`。
- 不存在 `assistant/chunk`。`assistant/message.data` 与仅日志用途的 `assistant/attempt.data` 都要求内嵌的 `stream`。
- surface 替换声明保留 `start` / `end`；系统提示词文本仍位于 `request/header.data.header.system`。不存在 V3 的 `system/message` 事件。

[V2 codec](../../../packages/session/session-format-v1-to-v2/src/codec.ts)负责每行一个事件的编码、范围编码的来源引用，以及从 `session/end-seed` 标记推导的继承切点。[V2 到 V3 规范](../../../packages/session/session-format-v2-to-v3/README.zh.md#v2-to-v3-specification)负责系统消息插入、PTC 事件名称与规范信封转换。

对于已继承的 V2 Session，最后一个携带 `data.inherited: true` 的 `session/end-seed` 事件以其序号位置标识继承切点。物理 `sourceEventSeqs` 可以使用范围编码；逻辑 schema 保留展开后的数值数组。

pnpm run verify-persistence-formats
